## 4. Phase B：`scripted_grasp_probe.py`——验证“物理上可以抓”，但绝不冒充RL

新建建议位置：`scripts/rsl_rl/scripted_grasp_probe.py`（如已有等效脚本，应复用而非复制）。其唯一作用是**实验/调试**，不修改正式训练策略输出。

### B1. 真实脚本抓取过程

在**训练集**`new_training_set/wood_block_oriented`或静态审计选出的另一个易抓物体上：

1. 使用现有预抓取IK确定无明显穿透、可达的机器人起点，展示实际TCP与物体top姿态和指尖位置。

## 5. Phase C：把GraspTrain改造成真正的“策略自主完整抓取”任务（核心源码开发）

> **关键边界**：脚本测试可以替机器人抬升；**正式PPO训练和`play.py`必须由策略自己输出UR5与Allegro动作来抬升。** 禁止采用“PPO只负责闭合，`play.py`在后半段硬编码抬升”并标记为完整RL抓取。

### C1. 新Task与语义隔离

- 优先复用`UR5AllegroGraspTrainEnvCfg`框架，但当前GraspTrain-v1为grasp-only衍生候选，**新语义必须独立标识**。
- 如果没有任何需要保留可加载的GraspTrain-v1正式训练Checkpoint，可在明确版本化`reward_semantics_version/action_semantics_version/observation_semantics_version`后改造v1；否则另注册`Grasp1-UR5-Allegro-GraspTrain-v2`，新PPO实验名与checkpoint目录分开。最终在报告中**只公布实际注册并运行的Task ID**，不随意重命名旧模型。
- 训练仍为标准Manager-Based：ActionManager、ObservationManager、RewardManager、TerminationManager、EventManager；课程可用CurriculumManager或明确的GPU张量状态实现，不手写第二套PPO。
- 仅使用训练集目录，不使用`shapenet-30obj`。首选从一个简单物体开始，并逐步向已有训练物体扩容。

### C2. 定义完整Episode和阶段逻辑

必须让同一回合有足够时间完成全部动作。以实测时间决定初始候选，例如先对照`6s/8s/10s`，**不是直接断言4秒不行**。至少定义：

| 阶段 | 要学的真实动作 | 阶段转换/要求 |
|---|---|---|
| Approach | UR5带手靠近可抓取区域，避免桌面撞击 | 手物距离、有效姿态、安全距离等真实信号 |
| Close/Grasp | Allegro形成接触与夹持 | 多指有效接触与稳定性；仅“数量≥2”不等于力闭合 |
| Lift | **策略自己**输出UR5上抬动作，手仍控制抓握 | 物体top离桌、相对手保持、未依靠碰撞弹起 |
| Hold | 策略继续维持夹持和物体离桌 | 连续保持一段时间，接触与位姿稳定 |

- 可采用**分阶段课程训练**（先掌握接近闭合，再强化抬升保持），但最终部署/`play.py`只加载一个一致的策略，实现完整流程。
- 阶段状态、剩余时间、目标高度/方向如果在奖励或环境内影响最优动作，必须在策略观测中提供必要的可观测信息，避免隐藏相位造成不可学习的POMDP；不将未来结果或特权成功标签泄漏给actor。
- 状态机只负责阶段目标、奖励、允许的重置/终止，**不在Lift/Hold阶段偷偷覆写策略的机械臂target**。任何辅助动作/示范动作仅在独立课程实验中标注，最终必须去除辅助并重新测自主成功率。

### C3. Observation：以完整抓取可学习为准，不僵守153D

检查现有153D观测是否包含策略完成抬升所需信息。推荐最小补充：

- 物体top相对手掌或腕的位姿、线/角速度或可推断的相对运动；机器人关节实际q/qd与控制目标偏差。
- 物体相对**真实桌面顶面**的高度、目标抬升高度差；当前阶段/阶段目标或剩余时间。
- 有效手物接触的稳定指标；避免仅用contact存在位表达完全夹紧。
- 数值裁剪/尺度归一化依据真实数据，特别是接触/冲量和角速度极端值；所有非有限值触发异常诊断，不静默伪造0。
- 如果变更153D观测，必须同步PPO网络输入、ObservationManager、`play.py`和Checkpoint签名；**禁止将旧153D预训练权重强行当作新维度可兼容**。如需要迁移，做独立适配实验并明确改层。

### C4. Action：必须真正具备闭合与上抬的可达性

- 默认保持22D（UR5 6 + Allegro 16）控制顺序与相对关节位置控制；先量化手指闭合所需的角位移、UR5达到指定桌面上方高度所需的关节轨迹、目标饱和比例、实际速度、effort以及动作时间预算。
- V2.1 GraspTrain D4名义Action Scale是arm`0.0008333`、hand`0.0025`，D2是arm`0.0004167`、hand`0.00125`；这是**时间等效候选，不是证明机械臂能够抬升的充分条件**。需要在真实控制条件下做开环/闭环试验。
- 若幅度不足，可在新Task中尝试分关节action scale、速度受限的位置目标、合理的抬升方向控制或明确的任务空间动作；必须记录动作语义、执行限位/速度/torque约束，并在实验中验证安全性和自主控制能力。
- 不能让Reward要求Lift，但动作空间没有足够幅度/时间能够Lift；也不能强行将策略输出截断到无法上抬的范围。
- `sim.dt`不变；控制频率与Episode改变后，`gamma/lam`、rollout模拟时长和Reward dt换算应同步或解释选择。

### C5. Reward：保留源物理含义，但为完整抓取增添真实目标

- 新建建议`mdp/rewards_full_grasp.py`（或一个清晰的独立新Task reward模块），原`rewards.py`/`rewards_grasp_v1.py`作为参考和回归，不直接覆写旧Teacher定义。
- 先使用优化8已审计的PhysX接触冲量方向和单位：传感器力×**一个真实物理dt**，不要因D4而再乘4；对原RaiSim逐接触过滤无法等价这一点保持明确说明。
- Reward分项至少包括：接近目标、有效手指接触与多指对向夹持、物体真实离桌高度、随手抬升而非碰撞弹飞、成功保持持续时间、桌面/机器人非法碰撞、过大控制/速度/关节异常。
- **严格检查并处理原Teacher `obj_vel_reward_`(−15)和`obj_displacement_reward`(−5)**：它们在上抬阶段可能与任务目标直接冲突；建议按阶段条件化或调权重，不能保留原值不加论证就同时奖励Lift。
- 力/冲量奖励必须限制刷分方式：避免策略通过拍打、反复撞桌、大冲量或让物体弹飞获得比稳定夹持更高的回报；按真实接触、离桌高度、保持时间设计检验。
- 阶段奖励正确处理`RewardManager`的`env.step_dt`乘数。稀疏成功奖励/终止奖励应按**一次事件**计算，避免D2和D4中因dt重复放大或缩小。
- 给每项奖励做方向/单位/数量级单元测试，建立抓取时序下的真实分布日志：平均、p50/p95/p99、相对总Reward贡献、是否受尖峰主导。**禁止仅靠Reward上升宣称成功。**

### C6. Reset、Curriculum与Termination

- 第一阶段只选训练集中的一个易抓物体，缩小物体XY、yaw、手掌到目标的距离和IK预抓取难度；统计`ik_feasible`、初态碰撞、可抓取率及Episode内首接触时间。不能通过先把物体装到手里创造“从零学抓”的虚假成功。
- 保留合理的预抓取先验属于任务设置，但应明确**最终策略学习的是完整自主抓握和上抬**；后续再逐步增加位置、朝向和物体难度。
- 原`apply_object_position_bias`在靠近后移动物体的机制，初期课程建议禁用或受控实验。禁止让策略刚要接触时物体被reset事件“偷偷”移动而产生不可学习的不连续性。
- 审查原`invalid_hand_height`“任一关键点低于桌面立即终止”是否误杀合法的抓取姿态；按真实穿透和碰撞安全定义新Task终止，而不是取消所有保护。
- 明确成功、掉落、碰撞、超时、非有限/严重物理异常的不同终止原因；成功必须连续保持足够时间，不允许单帧超过高度线就终止并报成功。
- 初期课程可以从易到难推进，但必须有量化晋级/回退条件；训练集物体列表、范围、课程序号、权重必须随Checkpoint保存，续训语义清楚。

### C7. Gate C

- 新Task在**训练集**单物体场景可运行；至少检查1env、16env、128env（显存不足留证）；真实Action/Observation/Reward/Termination/partial reset数据一致。
- 开环/脚本运动测出**策略动作空间有足够的可达性**完成闭合+自主上抬；Reward正向激励真实完整抓取，负项不形成不可逾越障碍。
- 可复现的状态机/阶段转换，不存在未向Actor提供的关键阶段变量（或明确给出可学习的无状态方案）。
- 保留旧Teacher正常注册和启动；不兼容的新Checkpoint被清楚隔离。

## 6. Phase D：先用训练集证明PPO真的学会“自主完整抓取”

### D1. 控制变量的训练候选

1. 以一个真实脚本可抓的训练物体为起点，从`128–256 env`的小规模训练开始；不能因为RTX3070Ti 8GB显存限制而盲目先开2048env。实测FPS、VRAM与环境稳定性，再递增。
2. 初始以`D4=30Hz`为候选，D2为必要时的对照；依真实动作可达性决定，不要为了名义吞吐牺牲有效动作。
3. 网络可先以现有128×128做基线；观测输入归一化、LR约`3e−4`、rollout32等只作为实验候选。因任务更改需要调参时每次尽量**单变量或少量变量**对照。
4. 分阶段短训：先跑100次更新确认张量、动作、Reward分布与物理安全；再500次；如果有行为改善再到1000次。**这些次数不是成功保证。**
5. 不允许将已改变Obs/Reward/Action的模型加载成语义一致的正式续训；必要时从头训练，并保存实验比较。

### D2. 训练日志必须与真实动作对应

每50–100个PPO update至少记录：

- PPO：总/分项Reward、value loss、approx KL、entropy、action std、梯度/学习率、explained variance（如支持）、训练FPS/显存/墙钟。
- 物理：实际q/qd峰值、越限最坏值、target饱和、effort、接触力异常、reset失败比例及异常终止。
- 抓取：接近率、有效多指接触率、物体持续离桌率、**策略自主完整抬升保持成功数/总数**、平均保持时长、物体top高度曲线、掉落原因。
- 训练集物体名称和reset姿态随机种子；不能只呈现Reward曲线、不呈现成功率。

### D3. 不强制引入独立验证集

- 从同一个`new_training_set`物体池选择训练物体，使用若干**训练集内固定重置种子**作为可复现的进度测试；这些是训练集表现诊断，不要写成held-out泛化成绩。
- 每次用**确定性Actor**纯策略动作执行完整Episode，禁止在Lift阶段替策略发送任何脚本动作。
- 与随机策略、空动作和脚本可抓基线区分对比；成功指标按实际多次试验计算，避免某次偶然抛物被当成功。
- 若短训没有可重复成功，优先排查：预抓取距离/角度、Action有效运动、Reward方向和尺度、抬升阶段观测、控制/接触稳定、critic/动作分布；**不要只增加训练迭代**。

### D4. Gate D（正式长训前必过）

- 能持续PPO更新而无未解决的真实物理异常，Critic与动作分布未严重恶化。
- 使用训练集物体、不同reset初态，能观测到**完整流程的实际自主抓取成功**，且优于随机/空动作基线；至少有可重复非零成功，推荐工程起步≥`3/20`，不把它当成最终性能承诺。
- 训练得到的`.pt`能够在下面的Phase E用GUI**纯策略**完整播放。若达不到，返回Phase C做有根据的修改并短训，不直接开启8–10小时正式训练。
