## 1. 一页结论

**优化8没有实现“可正常训练，并在8–10小时后得到成功抓取”的最终目标。** 这是证据明确、且执行报告未隐瞒的结论：`task_complete=false`，物理Gate A=`fail`，B/C/D/F/G=`blocked`；正式训练更新数=0、transitions=0、评估次数=0，故成功率为`null`，**不是0%**。优化8的价值主要是复现异常、独立创建新Task、审计Reward、验证新契约的合成用例，以及证明源Teacher网络在CPU上可等价映射。

但审查还发现一个**尚未在执行报告中充分指出的真实代码缺陷**：`scripts/rsl_rl/evaluate.py`在配置ShapeNet实际评估资产**之前**运行checkpoint资产兼容性验证，使新Task的“评估对象内容校验”没有覆盖真正运行的对象。另有契约对Python实现变更/部分传感器与物理配置覆盖不完整、课程和正例验证尚未落地等问题。

**总体判定：`NOT_READY_FOR_FORMAL_RL`。** 不建议绕过Gate强行开展8–10小时训练；建议优先修复真实物理问题与评估契约漏洞，取得能抓起物体的脚本正对照，再开始500–1000次更新的短PPO验证。没有数据能保证修复后8–10小时一定成功。

## 2. 严重程度与证据规范

- **P0 / 阻断**：直接使本目标无法安全启动训练，或无法给出实际成功证据。
- **P1 / 应修复**：已定位的代码缺陷、MDP/配置重大设计缺口，或正式训练前必做的验收缺口。
- **P2 / 优化**：复现性、工程维护、吞吐、统计和实验效率方面的问题。
- **已证实**：当前源码顺序/配置或现存真实数据足以证明。
- **待验证**：静态风险或合理机制，**尚无因果实验**；不能当作确定根因。
- **未运行**：根本不存在实测样本，不能从空表推出失败率。

### P0-02：物理异常的具体根因仍无证据【已证实为未定位，原因待验证】

### P1-05：源Teacher `70×0.2=14s`实际抓取rollout与新Task 4s存在任务时域差异【设计风险，非自动错误】

原RaiSim `train.py`的`grasp_steps=70`、`control_dt=0.2`意味着单次训练抓取序列约**14秒**；源YAML的`max_time=4s`不等于该实际rollout。新Task配置`episode_length_s=4.0`，D4控制30Hz下每回合约120动作机会；源70次5Hz动作在物理秒数和策略决策次数上各有不同。当前同样保留4s旧Teacher作为基线并没有证明4秒足以形成有效手指包络和持续夹持。

**整改**：在脚本正例基础上用4s/10s/视需要14s的**同物理条件**进行时间分布和短PPO对照，不通过延长horizon掩盖物理错误；记录接触时刻、对向夹持持续时间、失败率、样本效率、吞吐和wall成本。优先满足可学性而不是生硬模仿源时长。
