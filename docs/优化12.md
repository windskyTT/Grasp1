3. 100次安全且至少出现有意义的学习信号后，再在**明确区分从头训练/接续训练**的前提下推进到500次，必要时到1000次。不得把多段训练的累计更新编号写错。
4. **至少每50次保存Checkpoint**，保存权重、当前课程配置、动作/观测/奖励语义、真实完成更新数和物体信息。出现策略退化时保留较早的有效模型。
5. 仅在初步学习已被证明、资源可行且有明确实际训练收益时考虑8–10小时训练；失败阶段提前停止、输出诊断，不“挂机消耗时间”冒充任务完成。

### C2. PPO真实训练监控

每次更新或按适当间隔记录：

- Actor/Critic Loss、KL、Entropy/Action Std、学习率、梯度范数、数值非有限检测。
- 各项Reward的平均、积分贡献、同一Episode总回报；特别关注Approach、Grasp、Lift、Hold、Success、Failure、Table Contact、Joint Limit。
- 平均回合长度、Reset有效率、真实unsafe / dropped / time_out / success比例。
- 各阶段进度：手指接近、至少两个相向接触、有效夹持、抬升高度、连续Hold时长；**Reward上升必须与这些行为指标交叉验证**。
- 安全投影统计及真实目标跟踪误差，实际物体接触/桌面支撑/动作饱和情况。
- 吞吐量、真实墙钟、GPU驱动显存峰（采样口径注明）、PyTorch分配峰。

### C3. 训练初期学不到抓取时的故障定位顺序

如果100次后全程无有效夹持/抬升，按如下顺序**一次只调整一个主要因素**：

1. Reset有效性、起点与物体相对位置、距离/姿态/关节限位以及动作可达性。
2. 动作经过`clip→scale→累计目标→投影→真实执行`后的实际范围；是否有系统性卡住。
3. Reward是否产生梯度可用的方向信号；惩罚是否压倒接近/夹持奖励；成功事件是否只记一次。
4. 探索噪声和PPO学习率的有限对照，例如围绕当前`LR=3e-4`、`init_std=1.0`、`min_std=0.2`比较，但**不得同时修改奖励、网络和动作定义再归因**。
5. 如纯PPO难以从随机策略探索到脚本成功轨迹，可以新增**可选择的成功脚本演示→行为克隆(BC)预训练→PPO微调**实验；BC必须仅监督机器人动作、记录演示数据来源，训练完成后仍须是**独立纯Policy自主闭合和抬升**，不允许在播放过程中调用脚本。
6. BC/PPO混合训练必须说明采用的新训练流程及Checkpoint来源；不声称仍是“纯随机初始化PPO”。

**Gate C：** 至少完成**真实**100次PPO更新、有有效新`.pt`和配套配置、无物理致命异常，并提交可复现的训练曲线与首轮纯Policy回放。若100次尚无成功但学习迹象明确，可继续限量实验；若无学习迹象，先修训练问题。未产生模型时Gate明确`fail/blocked`，不得继续假装完成。

## 6. Phase D：训练集固定协议比较Checkpoint，判断是否“越训越差”

使用脚本：

- `scripts/rsl_rl/play.py`（**主要的策略GUI及训练集播放入口**）
- `scripts/rsl_rl/compare_training_checkpoints.py`（只做必要改进，**非主要开发目标**）
- `scripts/rsl_rl/checkpoint_contract.py`

### D1. 不混用的三种结果

- **训练采样成功率**：PPO训练使用随机动作采样，含探索噪声。
- **纯Policy推理成功率**：`play.py`载入Checkpoint，确定性推理，物理条件和Reset种子固定；这是选择最好模型的主要依据。
- **脚本成功率**：仅作为已知可抓性上限参照，不纳入Policy统计。

### D2. 固定训练集协议

1. 使用同一训练集木块及相同20个或更多起始状态/随机种子；固定场景、动作、观测、成功判定和课程。**不是验证集测试。**
2. 优先构造并保存实际Reset状态清单（物体pose、机器人q、手掌/TCP pose、随机因素）。不同Checkpoint读取**相同的真实初态**；不能仅依靠不同进程给同样种子就假设一切一致。
3. 比较100/200/300/500等真实存在的Checkpoint，逐个保存：成功数/分母、unsafe、drop、timeout、最大抬升、稳定保持时长、平均结束时间、各阶段进度和策略动作异常。
4. 推理必须只调用`policy(obs)→env.step(action)`；禁止额外的scripted控制器；GUI可用`--show_frames`核对法兰、掌、TCP和四tip。
5. 检查成功率确实下降时：对照KL、Critic loss、Actor Std、目标饱和率、投影比例、课程变动和Reward构成；给出证据链后再调整超参数。
6. 将成功率的统计不确定性写明；20次仅作早期诊断，不应将偶然1–2次差异判定为显著退化。

### D3. 比较工具的最小必要改进

当前比较脚本对每个模型每个种子都单独启动一次Isaac Sim，耗时巨大。**优先在同一进程使用多个环境测试一个Checkpoint**，并以保存的初态清单保证模型间条件一致。每个模型使用独立仿真进程可以接受；不要再每个回合都重新启动。

输出两个**严格区分**的产物：

- `best_success.pt`：只有存在**真实完成稳定Lift/Hold**的模型才能生成；并复制/生成准确的元数据。
- `best_progress.pt`：当成功率均为0，但某模型有更好的接近/夹持/抬升阶段进度时可保存；报告明确它**尚未抓取成功**。

原来供`play.py`使用的`best.pt`可作为真实成功最佳模型别名；**绝不能将仅有学习进展的模型标注为成功`best.pt`**。

**Gate D：** 至少比较2个真实新模型的固定训练集表现；模型若都没成功，仍保留准确统计与学习进展，不伪造“成功率提升”。

## 7. Phase E：实现C1→C2→C3的显式Warm Start

**这是训练流程必修项，不是允许任意Checkpoint强行覆盖兼容性检查。**

主要文件：

- `scripts/rsl_rl/train.py`

### E1. 两种恢复模式必须分开

**严格Resume**：环境、动作、观测、Reward、课程分布均兼容时，恢复Policy/Value网络、优化器、训练进度及规范支持的运行状态；继续保持原有严格契约比较。

**Warm Start**：从C1训练成功模型加载**明确兼容的**Actor/Critic网络权重及必要的观测归一化统计，新课程按新配置创建训练任务、重新建立优化器和课程内更新计数，记录来源Checkpoint、原课程和目标课程；允许Reset位置分布改变，但不得改变动作/观测含义而不转换。

实现要求：

1. 先读取本机实际RSL-RL 3.1.2保存结构，再编写加载实现；不要猜测`.pt`键名。
2. 检查网络输入输出维数（v3当前211D/22D）、动作顺序、TCP语义、奖励阶段、姿态约定、资产是否可比。存在实质性语义变化时直接拒绝或提供明确的映射方案，不静默加载部分张量。
3. Actor/Critic的观测归一化统计需要与网络权重一起审计；必须避免“复制权重却忘记归一化”导致的策略退化。
4. Warm Start后的第0次更新之前，在新课程固定初态进行真实Policy前向/动作范围/碰撞安全烟雾测试。
5. 记录源Checkpoint、训练累计更新与目标课程内部更新；策略迁移不等于目标课程已有抓取成功。
6. 同一课程的普通Resume继续严格拒绝错配，不通过`--allow_mismatched_checkpoint`绕过训练安全性。

### E2. 课程推进规则

- **C1**：单木块、近距离预抓取；达到可重复抓取成功后再考虑下阶段。
- **C2**：桌面中心、TCP桌面上方0.30 m；使用C1 Warm Start并验证可到达/可学的完整抓取。
- **C3**：桌心上方0.50 m（世界坐标 `(0.2,-0.75152,1.271)` m），从C2 Warm Start；**先完成脚本全流程时间预算**，再投入策略训练。
- 每次扩展初始姿态或物体范围都保留原课程配置和Checkpoint。若新课程退化，可以退回该课程之前最优的模型重新尝试，不覆盖有效成果。

**Gate E：** Warm Start可加载已验证兼容权重、正确恢复归一化、能够真实执行新课程短更新；不存在新模型时只完成接口测试并明确 `blocked_no_source_policy`，不能伪造成功迁移。
