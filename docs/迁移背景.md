# Part B. IsaacLab 原生代码架构原则

# 4. 总体原则：优先使用 IsaacLab abstraction

不要把 IsaacLab 当作：

```text
PyBullet
Gazebo
MuJoCo
旧 Isaac Gym
```

的简单替代 API。

IsaacLab 是建立在：

```text
Isaac Sim
PhysX
USD
PyTorch
GPU tensor
Vectorized environments
```

之上的机器人学习框架。

编码优先级：

```text
1. IsaacLab abstraction
2. PyTorch vectorized tensor operations
3. Isaac Sim API
4. Raw USD / PhysX API
```

只有 IsaacLab 没有合理上层接口时，才考虑更底层 API。

禁止为了机械复刻旧项目而大量绕过 IsaacLab abstraction。

---

# 5. Manager-Based 核心思想

Manager-Based 项目不应围绕一个巨大的 Environment 类组织。

核心结构：

```text
ManagerBasedRLEnv
│
├── Scene
├── ActionManager
├── ObservationManager
├── RewardManager
├── TerminationManager
├── EventManager
├── CommandManager
└── CurriculumManager
```

推荐思想：

```text
Function
+
Config
+
Manager
```

不要把：

```text
observation
reward
reset
termination
action
randomization
```

全部塞进一个巨大 env class。

---

# 6. 配置驱动，而不是自己重写主循环

传统代码可能写：

```python
sim = Simulator()
robot = load_robot(...)

while True:
    action = policy(obs)
    robot.set_action(action)
    sim.step()
    obs = ...
    reward = ...
```

Manager-Based task 不应重新实现这种 simulation 主循环。

应声明：

```python
class MyEnvCfg(ManagerBasedRLEnvCfg):
    scene = ...
    observations = ...
    actions = ...
    rewards = ...
    terminations = ...
    events = ...
```

然后由 IsaacLab 管理：

```text
action
→ simulation
→ observation
→ reward
→ termination
→ reset
```

禁止在 Manager-Based task 中自行重复调用 `sim.step()`。

---

# 7. Config 和 Runtime Object 必须严格区分

例如：

```text
ROBOT_CFG
```

只是配置。

运行时真正机器人是：

```python
robot = env.scene["robot"]
```

同理：

```text
RewardTermCfg
```

只是 reward term 声明。

真正计算由：

```text
RewardManager
```

在 runtime 执行。

必须牢记：

```text
Cfg
=
声明如何创建 / 配置 / 调用

Runtime Object
=
真正的仿真对象或 runtime state
```

不要混用二者。

---

# 8. Tensor-first + Batch-first

RL runtime 默认使用：

```python
torch.Tensor
```

而不是 NumPy。

典型状态：

```python
joint_pos = robot.data.joint_pos
joint_vel = robot.data.joint_vel
```

典型维度：

```text
[num_envs, num_joints]
```

例如 UR5 + Allegro：

```text
6 arm joints
+
16 hand joints
=
22 joints
```

在 4096 环境时可能是：

```text
[4096, 22]
```

所有：

```text
observation
reward
action
termination
reset
randomization
```

默认都要先考虑：

```text
[num_envs, ...]
```

---

# 9. 禁止优先使用逐环境 Python 循环

不要优先写：

```python
for env_id in range(num_envs):
    ...
```

应尽量写：

```python
distance = torch.norm(hand_pos - object_pos, dim=-1)
reward = torch.exp(-scale * distance)
```

如果只处理部分环境：

```text
使用 env_ids 做 Tensor indexing
```

例如：

```python
object_pos[env_ids]
```

而不是 Python 遍历每个 env。

---

# 10. Partial Reset 是核心要求

并行环境中，通常只有部分 env 需要 reset。

reset / randomization 函数应天然支持：

```text
env_ids
```

适用于：

```text
robot reset
object reset
velocity reset
pose randomization
domain randomization
```

不要因为少量 env done 就重置整个 simulator。

---

# 11. 避免 GPU → CPU → GPU 数据回流

不要在每个 RL step 中频繁：

```python
tensor.cpu()
tensor.numpy()
np.array(...)
```

因为会形成：

```text
GPU
→ CPU
→ NumPy
→ GPU
```

NumPy 适用于：

```text
离线预处理
文件读取
配置生成
一次性初始化
```

核心 RL runtime 尽量使用 batched Torch。

---

# 12. Scene 应由 SceneCfg 管理

不要：

```text
for env_id:
    load_robot()
    load_object()
```

应定义 scene template：

```text
robot
object
table
light
sensor
```

再由 IsaacLab 根据：

```text
num_envs
env_spacing
```

进行 scene cloning。

思想：

```text
定义一次 scene template
→ clone N 个环境
```

---

# 13. Prim Path 是核心概念

典型 USD scene path：

```text
/World/envs/env_0/Robot
/World/envs/env_0/Object
/World/envs/env_0/Table
```

配置常使用：

```text
{ENV_REGEX_NS}/Robot
```

因此任何 asset/task 迁移都要检查：

```text
prim_path
asset hierarchy
link/body names
joint names
```

很多：

```text
robot 找不到
contact sensor 不工作
body lookup 失败
```

本质都是：

```text
path/name mismatch
```

---

# 14. Asset 和 Task 分离

Asset 表示：

```text
机器人是什么
物体是什么
```

Task 表示：

```text
机器人要做什么
```

同一个 UR5 + Allegro asset 应能被多个 task 复用。

因此：

```text
robot physics / actuator / USD
→ robots/ur5_allegro_cfg.py

grasp task behavior
→ tasks/manager_based/grasp1/
```

不要把 robot config 写死进 reward/events/task logic。

---

# 15. USD 是主要 runtime Asset 格式

旧项目可能使用：

```text
URDF + STL + OBJ
```

IsaacLab / Isaac Sim runtime 应优先使用：

```text
USD
```

推荐工作流：

```text
URDF + Mesh
→ 转换 USD
→ 验证
→ runtime 使用 USD
```

但：

```text
保留原始 URDF / OBJ / STL
```

不要假设每次环境启动都自动得到生产级 USD。

---

# 16. Action、Controller、Actuator 必须分层理解

策略输出：

```text
Policy
→ ActionTerm
→ scale / offset
→ joint mapping
→ controller
→ actuator
→ PhysX
```

不能看到旧代码中的：

```text
action
```

就直接假设它是：

```text
joint position
joint velocity
torque
```

必须先确认物理语义。

同时区分：

```text
RL Action
↓
ActionTerm
↓
Controller
↓
Actuator
↓
Physical Joint
```

Actuator 可能配置：

```text
stiffness
damping
effort limit
velocity limit
```

不要把：

```text
policy output
```

和：

```text
真实 motor torque
```

混为一谈。

---

# 17. Observation 使用 ObservationManager

不要把所有 observation 都混在一个巨大函数中。

优先拆成可组合 term：

```text
joint_pos
joint_vel
object_pose
relative_position
last_action
contact_state
keypoints
affordance vectors
...
```

然后由 ObservationManager 组成 ObservationGroup。

Teacher / Student 场景尤其适合：

```text
Policy Observation
Critic Observation
Privileged Observation
```

但当前阶段只迁移 Teacher，除非后续任务明确要求，否则不要提前实现 Student observation。

---

# 18. Reward 使用 RewardManager

不要在 step() 中写一个巨大：

```python
reward = 0
reward += ...
reward -= ...
```

而应拆分多个 RewardTerm：

```text
Function
+
Weight
+
Params
```

优点：

```text
reward tuning
ablation
logging
weight adjustment
```

RobustDexGrasp 原有 reward 迁移后，应统一拆入 `mdp/rewards.py`，再由 `teacher_env_cfg.py` 配权重。

---

# 19. Termination 独立管理

Termination 不应混入 reward。

典型 termination：

```text
timeout
invalid robot state
simulation instability
object dropped
object too far
success
```

但对于本项目：

> 第一阶段以原 RobustDexGrasp Teacher 行为等价为优先。

不要为了“看起来更完整”随意加入新的 early termination。

---

# 20. Reset / Domain Randomization 优先放 EventManager

应该优先把：

```text
reset
randomize mass
randomize friction
randomize pose
disturbance
```

放入 EventManager。

常见 mode：

```text
startup
reset
interval
```

RobustDexGrasp Teacher 的：

```text
object sampling
robot initial pose
pre-grasp
IK
collision fallback
```

主要应迁移到：

```text
mdp/events.py
```

---

# 21. CommandManager / CurriculumManager 按需使用

如果存在明确 target：

```text
target EE pose
target object pose
target velocity
desired orientation
```

可以考虑 CommandManager。

但：

```text
不要为了架构形式完整而强行增加 CommandManager
```

CurriculumManager 适合：

```text
逐步增加 pose randomization
逐步增加 object 类型
逐步增加 mass/friction randomization
逐步增加困难抓取场景
```

当前第一阶段优先行为等价，不要擅自把原有 biased sampling 改写成新的 curriculum。

---

# 22. Environment Config 与 Agent Config 严格分开

Environment config 负责：

```text
scene
robot
object
num_envs
observation
action
reward
reset
termination
simulation
```

Agent config 负责：

```text
Actor
Critic
PPO
learning rate
gamma
lambda
clip
entropy coefficient
rollout length
max_iterations
checkpoint
```

不要把：

```text
max_iterations
```

放到 EnvCfg。

不要把：

```text
num_envs
```

误当 PPO 网络配置。

# 23. 与其他仿真代码范式的区别

## Gazebo / ROS

Gazebo/ROS 常围绕：

```text
Node
Topic
Service
Publisher
Subscriber
ros_control
```

IsaacLab RL loop 主要围绕：

```text
Env
Tensor
Observation
Action
Manager
GPU batch
```

核心训练数据流不要依赖每一步 ROS publish/subscribe。

## PyBullet

PyBullet 常见：

```text
loadURDF()
getJointStates()
setJointMotorControlArray()
```

IsaacLab 优先：

```python
robot = env.scene["robot"]
robot.data.joint_pos
robot.data.joint_vel
```

不要逐 joint 请求 simulator。

## MuJoCo

MuJoCo 常直接操作：

```text
model
data
qpos
qvel
ctrl
```

IsaacLab 更强调：

```text
Asset abstraction
Scene abstraction
Manager abstraction
GPU Tensor
```

## 旧 Isaac Gym

旧 Isaac Gym 常见：

```text
create_sim()
create_envs()
create_actor()
acquire_*_tensor()
pre_physics_step()
post_physics_step()
compute_observations()
compute_reward()
reset_idx()
```

迁移到 IsaacLab 时：

```text
create_sim/create_envs
→ SceneCfg

robot/object creation
→ AssetCfg / SceneCfg

state tensors
→ Asset.data

pre_physics_step/apply_actions
→ ActionsCfg / ActionManager

compute_observations
→ observations.py

compute_reward
→ rewards.py

reset_idx
→ events.py

done logic
→ terminations.py

randomization
→ EventManager

PPO config
→ agents/rsl_rl_ppo_cfg.py
```

核心：

```text
迁移功能语义
≠
逐行翻译旧 API
```

# 25. IsaacLab 常见反模式

除非有明确必要，不要：

```text
1. 大量 Python for-loop 遍历 num_envs
2. RL step 中频繁 tensor.cpu()
3. RL step 中频繁转换 NumPy
4. 自己重新实现 simulation main loop
5. Manager-based env 内手动重复 sim.step()
6. 把全部 reward 写成一个巨大函数
7. 把 reset/randomization 散落在多个无关位置
8. 把 robot config 写死到 task logic
9. 把 PPO 参数写进 environment config
10. 逐行翻译旧 simulator API
11. 为每个环境手动 spawn robot
12. 绕过 Asset.data 频繁查询 raw simulator
13. 为正常 runtime reset 直接修改 USD prim，除非上层 API 无法完成
14. 假设 action 数值就是实际 joint command
15. 忽略 batch dimension
16. 忽略 env_ids / partial reset
```

# 26. Codex 实现功能时的判断顺序

每次实现功能前按以下顺序判断：

```text
第一步：
IsaacLab 是否已有标准 abstraction？

第二步：
能否用 batched Torch operation？

第三步：
reset/randomization 是否支持 env_ids？

第四步：
逻辑属于哪一层？
Asset / Scene / Action / Observation / Reward /
Termination / Event / Command / Curriculum / Agent

第五步：
这是 Config，还是 runtime computation？
```

迁移任何旧代码前先回答：

```text
1. 功能语义是什么？
2. 属于哪个 IsaacLab Manager？
3. 操作 robot/object/scene/obs/reward/reset/action/algorithm 中的哪一个？
4. 是否假设单环境？
5. 是否包含 CPU/NumPy dependency？
6. 是否能改为 batched Torch？
7. IsaacLab 是否已有标准实现？
```

只有回答后再写代码。

# Part C. RobustDexGrasp Teacher 专属迁移规则

# 27. 不做逐文件机械翻译

RobustDexGrasp 是 RaiSim 架构。

IsaacLab 是 Manager-Based 架构。

因此以下文件：

```text
Environment.hpp
train.py
RaisimGymVecEnvOther.py
```

不能简单翻译成几个同名 Python 文件。

必须根据语义重新拆分。

---

# 28. `train.py` 使用项目自带标准版本

目标：

```text
scripts/rsl_rl/train.py
```

直接使用 `./isaaclab.sh --new` 创建的 IsaacLab/RSL-RL 标准版本。

RobustDexGrasp 原 `train.py` 中：

```text
PPO rollout loop
PPO update
checkpoint saver
NormalSampler
custom PPO class
```

不迁移。

只迁移其中：

```text
object dataset logic
reset logic
pre-grasp logic
IK
reward shaping
evaluation semantics
PPO hyperparameters
```

对应：

```text
data/object_set.py
mdp/events.py
mdp/geometry.py
mdp/rewards.py
agents/rsl_rl_ppo_cfg.py
scripts/rsl_rl/evaluate.py
```

---

# 29. MDP 文件职责

```text
actions.py
    policy action → robot command

observations.py
    构造 policy / critic observation

rewards.py
    reward 数学公式

events.py
    reset / randomization / pre-grasp / IK orchestration

terminations.py
    episode termination

geometry.py
    坐标变换 / rotation / visible point / grasp candidate / IK helper

keypoints.py
    hand / arm keypoint 批量计算

__init__.py
    对外导出 MDP API
```

其中：

```text
actions.py
observations.py
rewards.py
events.py
terminations.py
```

属于 Manager-Based 的直接 MDP 层。

```text
geometry.py
keypoints.py
```

属于任务内部辅助计算。

# 30. Teacher Action 语义

Teacher：


# 50. Evaluation

原：

```text

quantitative_eval.py
```

目标：

```text
scripts/rsl_rl/play.py
scripts/rsl_rl/evaluate.py
```

`evaluate.py` 应负责：

```text

multiple trials
lift test
success threshold
per-object success rate
overall success rate
```

原 lift success 关键语义：

```text
object z - initial object z > 0.1
```

迁移后保持：

```text
抬高 0.1 m
```

的物理语义，而不是依赖旧 global-state index。

当前 `scripts/rsl_rl/evaluate.py` 还要求环境在抓取和抬升阶段均未提前终止，
即 `active & (object z - initial object z > 0.1)`。
原 `quantitative_eval.py` 只按高度差 `> 0.1` 统计成功；
因此当前成功率定义更严格，不能直接视为与原评估成功率等价。

# 56. 每次修改代码的默认规则

每次收到后续具体任务时：

1. 先检查目标文件是否存在。
2. 已存在时优先最小修改。

10. 优先使用 IsaacLab 2.3.2 abstraction/API。
11. runtime tensor 计算优先 Torch + batch。
12. reset/randomization 优先支持 `env_ids`。
13. 避免不必要的 CPU/NumPy round-trip。
14. 类型注解和 docstring 保持清晰但不过度。
15. 如果旧行为无法一一对应，明确记录差异，不要静默修改。
16. 如果需要原代码行为，先核实原函数真实逻辑，不凭名称猜测。
17. 不因 generic architecture example 改变本文明确指定的 Grasp1 目录结构。

```text

2. prim path / body / joint names 正确
3. actuator / controller 配置合理
4. 22D action 语义正确
5. 153D Teacher observation 语义正确
6. 17 hand keypoints 定义正确
7. affordance point cloud 语义正确
8. reward formula 与 weight 基本等价
9. reset sampling 基本等价
10. partial reset 正确
11. pre-grasp candidate generation 基本等价
12. IK / best candidate selection 基本等价
13. collision fallback 基本等价
14. episode / rollout 长度语义明确
15. lift success 判定等价
16. zero_agent smoke test 通过
17. random_agent smoke test 通过
18. RSL-RL 可以正常训练
19. checkpoint 可以正常保存
20. 多环境 GPU simulation 正常
21. runtime 不存在明显不必要的 GPU↔CPU 数据回流
22. 没有为了迁移旧代码而绕过 Manager-Based abstraction
```

最终代码应具备：

```text
Manager-based
模块化
Torch-first
GPU-friendly
Batched
支持 partial reset
Asset 与 Task 分离
Environment 与 Agent 分离
优先使用 IsaacLab abstraction
尽量避免 raw simulator API
易于 Debug
易于 Reward Ablation
易于 Domain Randomization
易于后续 Teacher/Student 扩展
易于多 object dataset 扩展
```

最终目标是：

```text
旧式单体 RL Task
        ↓
IsaacLab 原生 Manager-Based RL Project
```

而不是：

```text
旧式 Task
        ↓
仅仅放进 IsaacLab 文件夹中运行
```
