## 4. Gate A：首先证明 PhysX 机械手真的能够夹住并抬起物体

**这是进入新一轮 PPO 训练的首要门槛。** 用已有 Isaac Sim 环境/现有入口的交互内存控制，先选 `wood_block_oriented`，再选 `suger_box_oriented`，至少1环境，必要时16环境。保存同进程可恢复的实际机器人和物体状态（root、q/qd、目标、物体top、关节/观测/Teacher状态、可读随机状态）；注意无法保证恢复未暴露的PhysX求解器缓存，A/B仍需报告可比范围。

依次实施：

1. **零动作/小动作验收**：分别正负驱动四根手指各关节，验证关节符号、限位、目标 `q_target`、实际 `q`、`qd`、位置跟踪误差、PD饱和、碰撞点与摩擦力。不要假设所有关节同时正向就是闭合。
2. **受控合法接近与闭合**：在真实物体上通过UR5关节目标进入可接触位置，手指按真实运动方向闭合。使用真实碰撞、质量、重力、驱动和力矩限制；仅允许合法Reset时初始化物体，不得运行中修改物体位姿或禁用碰撞。
3. **建立并保持物理夹持**：检查拇指与其他至少一根手指在物体上的真实有效接触、法向关系、持续时长、手物相对滑移；固定合法关节目标保持一段明确记录的时间，不得以接触计数取代承重证明。
4. **真实抬臂**：受控地沿现有机械臂抬臂轨迹运动，判断物体是否随手离桌并满足严格 `>0.10m`。这是**受控物理可行性测试**，绝不能计入 PPO 自主抓取成功率。

记录：每物理步或控制步的关节命令、实际q/qd、力矩上限裁剪、4 tip（fixed和distal分别记录）、13接触槽、前臂/手桌碰撞、物体top高度、速度及手物相对位置；采样率明确写出。结果标记 `PASS / FAIL / BLOCKED / UNVERIFIED`，并给出成功/尝试次数，不能用单一好看的截图证明成功。

**若受控夹持失败：不要训练 PPO。** 首先排除预抓取几何、关节方向、碰撞体、力矩饱和和接触计算错误；随后根据证据选择**一次只改一项**：

- 有 `q_target-q` 长时间过大/驱动力不足/持续限位饱和证据：在现有 `ur5_allegro_cfg.py` 里做手部伺服增益或力矩/阻尼的**小范围有界阶梯测试**，每档检查振荡、穿透、非期望大力、实际速度和夹持力。`600/20` 只是原引擎参考，不得直接复制到PhysX。
- 关节目标可跟踪但物体滑脱：先审查碰撞mesh、接触法向和摩擦实现，再在有接触证据时单变量测试合理摩擦配置；不采用让物体凭空粘住的数值。
- 关节/IK方向错误：只修改被直接证明错误的索引、轴符号或UR5专属几何变换；优化11/12/17已通过的法兰装配不得推倒重来。

若合理参数范围和合法受控轨迹仍无法抓取，输出失败边界及下一验证项；不要用脚本移动物体“制造”物理通过。

## 5. Gate B：找出 PPO 为什么学不到有效抓取

在 Gate A 有至少可复现的真实夹持正例后，用 `model_6860.pt`、`model_11480.pt` 在**同一物体/匹配Reset实际状态**回放，分开记录：`Reset → 0 → 210 → 420 → 630 → 839`；首次接触/首次多指接触/首次丢失/首次手指目标饱和等事件要记录发生步。

- 手掌、17关键点、4tip到物体top和可见点云的真实几何关系；记录法兰姿态/预抓取方向，点云距离不是精确碰撞间隙。

## 6. Gate C：有证据地修复奖励与 PPO 学习问题

### C1. 奖励是否真的鼓励可保持的夹持？

保留并核对原17项源公式及其单位转换。选一段**真实受控成功夹持轨迹**与相似但失败的接触/推物轨迹，计算17项在整个14秒中的逐步值、累积值及排序；确认：

1. 双侧稳定夹持的累计奖励是否显著优于触碰一下后脱离、推开物体或在桌面拖动物体；
2. 物体线速度/位移、腕部速度、手桌惩罚是否过强，导致“尽量不动”比真实接近闭合更划算；
3. `RewardManager`时间积分、Impulse阈值、正负号和归一化是否正确；若有真实代码错误先修复错误，不立即设计新奖励。

如果实测显示**正确夹持没有比失败策略更高的训练回报**，允许按照如下顺序做单变量最小改动：

- 先对一项有反证的原奖励权重/时序做有限调整，并用正反轨迹比较；
- 若原接触奖励仍无法区分“随手抬起前可保持的拇指—其他手指接触”与无效接触，才考虑在现有 `rewards.py` 和 `teacher_env_cfg.py` 增加**最小必要的、纯真实物理可测的夹持引导项**（如持续对向接触/相对滑移的阶段性辅助，不能依赖未来成功标签或真实策略不可获得的信息）；要求明确量纲、门控、上限以及可被碰撞刷分的风险；
- 逐项与原17项基线做消融比较。不能因为引入辅助奖励便把原始任务声称为源码完全等价；**依然只在独立脚本抬臂评估中判定成功**，不能偷加自主Lift替换Teacher任务。

## 7. Gate D：真正验证“PPO能不能学会”，不再以两次更新代替训练验收

两次更新只证明训练接口能运行，**不证明学习**。新流程如下，不能跳过前置门槛直接再跑12小时：

| 阶段 | 必要工作 | 通过条件 |
| --- | --- | --- |
| D0 接口烟雾 | 现有 `train.py --no_log`，16环境、2次真实更新 | 153D/22D，finite，Reset隔离、无致命物理异常 |
| D1 小规模学习对照 | 在固定任务/采样协议上运行**200～500次PPO更新**，至少比较基线与**一个**经过Gate A/B验证的单变量候选；显存允许时16→32/64环境，保持相同采样量对比 | 接触、对向夹持、保持时间和回报方向性指标出现**可重复的真实改善**；仅Reward提高不算通过 |
| D2 扩展验证 | D1通过且没有安全异常，再运行约**1000～3000次更新**，必要时用128环境；不得自动跳到20,000次 | 独立采样/对象测试的抓取末接触和脚本抬臂指标持续改善，且未靠限位/碰撞刷分 |
| D3 独立成功评估 | 用**新语义兼容的新checkpoint**分别运行现有 `play.py`、`visual_eval.py`；先固定已知物体，再逐步扩到35种训练物体、独立种子 | 报告真实 `x/N` 严格抬臂成功率 `>0.10m`，真实接触保持率和失败明细；没有成功仍为FAIL，不能只看Train Reward |

若 Gate A未通过、发生非有限/大幅异常接触、训练强烈退化或连续两档训练没有可重复的夹持改善，则停止扩大训练，按已证明的问题回退/调整一个变量。**禁止默认重新进行12小时或20,000次更新**。如果资源不足无法完成D1/D2，标记 `NOT RUN/RESOURCE_LIMITED`，不得宣称解决了长期不收敛。

**公平性：** A/B使用相同对象、seed方案、实际可比Reset、环境数、数据量、训练预算、评估脚本和模型选择规则；不同控制频率方案按实际PhysX步/样本数报告。奖励变化时既报告各自Reward，也报告物理夹持/抬臂指标，**禁止跨不同奖励定义直接比较Reward标量大小**。对比过程出现不同随机状态/接触求解器缓存，诚实说明误差范围。

**策略成功的唯一定义**：策略在14秒抓取阶段自主输出22D动作，之后现有`visual_eval.py`仅执行固定脚本抬臂；真实物体在末端高出Reset root参考高度**严格大于0.10m**且未中途终止。不允许人为抓紧、关闭重力、传送物体、奖励更改成功条件或只回放受控脚本的抓取正例。受控夹持正例仅是物理门槛，绝不能计入 PPO 成功率。

## 8. Reset与原始物理差异：只处理实证阻碍

优化14尚未成功迁移原始 Reset 的“零动作0.2s碰撞判断→同物体副本替换→固定回退”；优化15取消迁移要求，优化17也没有证明原始等价接口。保留现有预抓取IK/限位/32轮采样/partial-reset隔离基线。

仅在实际发现 Reset初始穿透、首个物理步非预期接触对、初始物体不稳定等导致抓取学习受损时研究修复。`sim.forward()`不是完整PhysX碰撞步；不得把旧ContactSensor缓存、AABB/overlap或手工距离阈值伪装成源逐接触判据。若只能得到**PhysX适配的安全筛选**，必须与源判据区分标记 `ADAPTED`，量化误判与对训练采样的影响，确认并行1/16/128环境partial Reset不会推进其他环境时间；不具备可靠条件则保持现状、报告阻断。

原始RaiSim逐点冲量 `|J|<0.001N·s` 与PhysX聚合ContactSensor数据不可直接互换；不要对合冲量套用0.001阈值来伪造源等价。不因源PD数字较大就把当前PD设为600/20。参数调整必须遵守 Gate A 的受控稳定性测试。

## 9. 训练契约、兼容性和回归

只读观测、终端诊断或独立评估改动，不改变PPO训练语义时，可沿用旧checkpoint和semantic revision 7。**凡改变训练相关**动作尺度/更新频率、驱动参数、Reset采样、物理参数、奖励定义或PPO网络/输入，都必须：

1. 在现有 `teacher_env_cfg.py`/配置与 `cli_args.py` 契约路径里准确表达变更；**提升Teacher的semantic revision**，不能用旧revision 7加载旧权重伪装有效；确认实际 checkpoint infos 序列化反映修改（仅仅修改robot配置常量不保证契约的序列化值总能覆盖）。
2. 新任务训练从新模型开始；如要迁移旧权重，必须先严格证明网络维度、优化器状态与新任务契约可以按显式转移协议工作，并单独标注“迁移初始化”，**不能直接旧权重普通resume**。为避免实验混淆，首个对照优先全新训练。
3. 不要改旧checkpoint文件、旧训练目录，使用原训练入口；修改只限现有必要文件，FR3配置及逻辑保持不变。
4. 逐阶段回归：语法导入、1/16/128环境物理/Reset（128超显存时记录实际限制）、关节与传感器时序、两次PPO烟雾、独立GUI `play.py`（纯策略）和 `visual_eval.py`（策略+固定脚本抬臂）。确保GUI物体确实随手移动，不靠截图替代状态数据。
5. 改动如果需要恢复原值，对象/动作/奖励/指标回归必须使用**基线的正确契约**，不能绕过已有 `validate_teacher_checkpoint`。

**不要动**成功判据、14s训练与6s评估的基本协议、观测/动作维度和顺序、物体质量/重力/世界坐标；这些项目不是可以随意调整来提高成功率的旋钮。
