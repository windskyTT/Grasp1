## 1. 主要结论

当前代码保留了 UR5-Allegro Teacher 的 **22 维动作、153 维观测字段结构、17 项奖励的名称和基础系数，以及独立脚本抬升的基本思路**，但不能表述为原始程序的完全等价迁移。

主要行为差异包括：

1. 控制频率由 5 Hz 改为 60 Hz，物理频率由 100 Hz 改为 120 Hz；动作尺度并未按原始单位时间幅度等比例换算。
2. Allegro 手部 P/D 从原始文件的 `600/20` 改为 `3/0.1`，执行器及摩擦处理也改用了 PhysX 机制。
3. 机器人安装位置、桌子几何及工作区朝向改变，相关观测数值分布随之改变。
4. 接触冲量保留原公式的主体，但无法复现 RaiSim 的逐接触点过滤。
5. 重置的调度、IK 失败处理及接触预检流程改变。
6. 奖励按物理时间缩放；终止当步奖励与原 Python 训练循环的实际数据流存在差异。
7. PPO 网络、归一化、采样长度、优化参数及探索噪声约束改变。
8. 新增 checkpoint 契约、诊断统计和独立 FR3-Inspire Teacher；原 Student/DAgger 与真实机器人链路尚未迁移。

下文用“保留”表示公式或字段含义仍在，用“修改”表示实际任务/训练行为改变，用“新增”表示原链路没有的功能。`ADAPTED` 表示与原实现不完全等价的迁移适配；即使代码没有写这个标签，本文也会指出差异。

## 3. 仿真、时间与动作语义

### 3.1 修改：控制周期和动作尺度

| 项目 | 原始 UR5-Allegro Teacher | 当前 UR5-Allegro Teacher |
| --- | --- | --- |
| 物理步长 | `0.01 s`，100 Hz | `1/120 s`，120 Hz |
| 策略控制周期 | `0.2 s`，5 Hz | `2/120 s`，60 Hz |
| 一个动作保持的物理步数 | 20 | 2 |
| 抓取时长 | 70 个控制步，即 14 s | 840 个控制步，即 14 s |
| 臂部每步动作乘数 | `0.005` | `0.075 × step_dt = 0.00125` |
| 手部每步动作乘数 | `0.015` | `6.0 × step_dt = 0.1` |

两边都采用以下结构：

```text
q_target = clamp(q_measured + action_scale * policy_action, 原关节硬限位)
```

当前不是累计上一目标的动作，也没有在 PPO 输出端使用 tanh 或 `[-1,1]` 裁剪；`clip_actions=None`。动作目标在每个控制步算一次，在该控制步的物理子步中保持，速度目标为零。重置时目标同步到实际重置关节位置。这些结构保留了原始残差位置控制的主要含义。

但数值尺度发生了实质变化。以相同的恒定单位动作作尺度比较，原始臂部、手部每秒对应的残差目标幅度分别为 `0.025`、`0.075`；当前分别为 `0.075`、`6.0`，是原始的 **3 倍和 80 倍**。这是 `action_scale/control_dt` 的比值，不是对实际关节速度的测量或保证，实际运动仍由 PD、限位和接触决定。

因此，“控制频率变化，但单位时间动作作用等价”不符合当前代码。

证据：`O-Cfg:58–72`；`O-Env:230–244、601–640`；`C-Scene:18–20`；`C-Cfg:24–25、154–156、191–197`；`C-MDP/actions.py:18–35`；`C-PPO:13`。

### 3.2 修改：移除了原始随机单物理步延迟

原始每个控制步随机选择是否在第一个物理子步继续发送上一目标，然后才发送本步目标。当前两个子步直接发送本步缓存目标，没有这项随机延迟。`visual_eval.py` 也没有恢复它。

这改变了控制延迟分布，属于未等价迁移的控制语义。

证据：`O-Env:616–636`；`C-MDP/actions.py:24–35`；`C-Scripts/visual_eval.py:1–7`。

## 4. 机器人、桌子及动力学语义

### 4.1 修改：Allegro 手部 PD 与关节摩擦

原始配置指定 `hand_pd_file: Allegrotemp.txt`。该文件前 16 项均为 `600`，后 16 项均为 `20`；`AllegroSim.cpp` 读取后由 `hardware.hpp::setPdGains()` 写入机器人。当前 `C-Robot` 使用 `stiffness=3.0`、`damping=0.1`，两项数值均为原始文件的 `1/200`。

当前采用 PhysX `ImplicitActuatorCfg`、force drive，并显式设置手部力矩上限 `0.7`、速度上限 `7.0`、关节摩擦 `0.01`。原 URDF 的手部 `<dynamics friction>` 数值为 `5/10/12`，当前 URDF 仍保留这些字段，但运行时执行器会覆盖摩擦配置。因此，URDF 相同不代表实际执行器参数相同；跨物理引擎的摩擦参数含义也不能直接等同。

UR5 六轴 P/D 则逐项保留了 `UR5Identification_id5hz.txt` 的数值。即使这些数值相同，RaiSim PD 与 PhysX 隐式驱动仍不是同一求解过程。

## 6. 接触语义与诊断新增

### 6.1 ADAPTED：逐接触点过滤没有等价实现

原始按接触点丢弃 `|impulse| < 0.001` 的项，再将世界系冲量累加到接触槽。当前 PhysX 接口分别提供法向接触和 friction patch，代码将实际法向力与摩擦力相加，乘 **物理步长** 得到冲量；没有实现原始逐接触点过滤，也没有用聚合阈值冒充它。

两边都读取最后一个物理步的接触，而不是累积整个控制周期。当前仍以 `|J| > 0.01` 得到接触标志，但物理步长从 `0.01` 改为 `1/120`，相同恒定合力对应的每步冲量也改变。仅从 `J=F×dt` 换算，`0.01 N·s` 对应的恒定合力从 `1 N` 变为 `1.2 N`；这只是阈值量纲比较，不是实际接触力测量。

UR5 四个独立 tip 刚体的冲量被并回原始 distal 槽，保持原 13 槽解释。未在源映射表中的接触刚体仍按源 `std::map::operator[]` 行为归入槽 0。臂部碰撞计数采用真实 contact count，避免合力相互抵消时漏掉接触。

证据：`O-Env:793–817、841–890`；`C-MDP/observations.py:680–774`。

### 6.2 新增：接触和物理状态诊断

当前新增四个指尖接触、掌部及近端手指的桌面接触采样，以及以下统计：

- `good_contact`：DexSuite 风格多手指接触诊断，使用 `1 N` 门槛。
- `grip`：拇指与其他手指对向接触，包含接触力及位置方向的点积 `< -0.2` 条件。
- 当前/最大 lift、关节限位误差、差分速度、物体速度和首次非有限异常现场。
- `teacher_episode`、TensorBoard 分项奖励及回合终止统计。

**`good_contact` 和 `grip` 没有注册为训练奖励、终止或成功条件。** `tip_contact_threshold_N=1.0` 也不是新增的训练失败阈值。当前 `bad = ~finite & fresh`；关节速度过大、关节越界、接触力过大等诊断量不会单独触发异常终止。

因此，应将这些内容列为“新增诊断”，不能写成“当前仍在训练中使用 DexSuite 两指接触奖励/额外安全门槛”。

证据：`C-Cfg:115–144、160、168–180`；`C-MDP/observations.py:659–673、777–903`；`terminations.py:15–27`；`C-Scripts/train.py:82–147`。

## 7. 重置与训练物体分配

### 7.1 保留：数据集和物体几何元数据

两份 `new_training_set` 当前均有 35 个物体目录，目录遍历顺序一致。逐文件直接比较了这 35 个物体的 URDF、`top_watertight_tiny.obj`、`bottom_watertight_tiny.obj`、`lowest_point_new.txt`，共 **140 个文件，内容一致**。这不包含 USD 转换结果和所有其他 mesh 文件的等价性结论。

困难物体追加规则以及全列表重复两次的规则保留，当前构造的完整加权列表长度为 `2×(35+9)=88`。`top` 仍作为 affordance 区域，每个不同物体采样 200 点；非 affordance 网格小于 25 个顶点时使用远置占位中心的处理也保留。

### 7.2 修改：默认并行数改变物体出现比例

原始正常训练按完整加权列表建立 88 个环境。当前默认 128 个环境，`set_num_envs()` 按列表循环分配，即完整 88 项再接前 40 项。因此，默认物体比例不严格等于原始 88 环境比例；这是当前有消费者的实际采样差异。

物体在环境构造时分配，reset 时重采样位姿，不重新抽物体身份。改变 `--num_envs` 会改变参与训练的物体覆盖和重复次数。

证据：`O-Train:120–125、149–160`；`C-Cfg:167、199–211`。

### 7.3 保留主体，修改边界：预抓取采样和失败处理

保留的主体包括：半径 `0.45–0.75 m`、角度 `[-0.7π,-0.3π]`、`|x|<0.25`、均匀/Beta 边缘采样混合、随机 yaw、桌面以上 `2 mm` 初始间隙、射线可见点、10 个方向候选、`0.25 m` 预抓取距离，以及 UR5 投影宽度与第 5 轴角度评分。

实际流程发生以下变化：

| 环节 | 原始代码 | 当前代码 | 语义影响 |
| --- | --- | --- | --- |
| reset 调度 | 每次外层训练迭代统一重新采样；回合中失败由 C++ 恢复已保存初态 | Isaac Lab reset event 按结束的环境行重新采样 | 回合分布和各环境采样时刻改变 |
| IK 实现 | NumPy/Python UR5 解析 IK | Torch 批量解析 IK，保留 DH 参数和参考姿态 | 数值实现适配，不能据静态代码保证逐样本一致 |
| 无效候选 | 原评分可能选到不可行候选，其关节结果保持零 | 外层增加可行、有限及全部关节硬限位检查，不合格重新采样，最多 32 轮后报错 | 接受的初态集合改变 |
| 接触预检 | reset 后执行零动作一步，检查臂部碰撞；复制其他初态或使用固定替代姿态，再 reset | 当前 reset 没有这段物理步接触预检、复制和替代姿态流程 | 原始初始化接触筛选没有完整迁移 |
| 控制目标及缓存 | C++ 恢复保存的目标和状态 | 按指定 `env_ids` 同步 joint state、位置/速度目标、动作目标和接触参考 | 并行环境接口适配 |

采样混合也存在细节差异：原始先为每个环境选择均匀或 Beta 分支，再在所选分支内拒绝重采样；当前对未通过 `|x|<0.25` 的环境，每轮重新选择分支。因此，当前最终接受样本的均匀/Beta 分支比例不保证仍为原始的 50%/50%，不能把“都使用这两种分布”写成严格分布等价。

当前播放和独立可视评估仍使用 `non_uniform_sampling=True` 的训练配置；原始可视评估/训练内评估有均匀采样路径。因此，当前评估的初态分布也不能自动称为原始评估分布。

证据：`O-Env:381–444`；`O-Train:301–551`；`C-MDP/events.py:95–202、205–318、321–405`；`geometry.py:677–821、828–898`；`C-Scripts/play.py:36–44`；`visual_eval.py:42–49`。

### 8.2 修改：按控制时间缩放奖励和折扣

原始每 `0.2 s` 直接给出 `Σ c_i f_i`。当前配置 `weight_i=c_i/0.2`，Isaac Lab RewardManager 再乘实际 `step_dt=1/60`，因此：

```text
当前每控制步普通奖励 = (1/12) × Σ c_i f_i
gamma = 0.996 ** (1/12) = 0.9996660539892578
lambda = 0.95 ** (1/12) = 0.9957346812224394
```

这保留的是单位物理时间奖励强度和折扣衰减的换算意图，不是原始逐步奖励值。状态轨迹、动作和接触冲量本身已经变化，因此不能由这个换算推导完整回报等价。不能把 PPO 配置类中未同步前的 `gamma=0.99、lam=0.95` 当成当前训练入口实际使用值。

原始 `reward_r.clip(min=-2.0)` 没有赋值、也没有 `out=`，其返回值被丢弃；它在该训练代码中不实际裁剪 `reward_r`。当前未做这项裁剪，不能据注释认定“移除了已生效的 -2 奖励下限”。

证据：`O-Train:199–202、627–628`；`C-Cfg:116–137`；`C-PPO:27–30`；`C-Scripts/train.py:46–48`；本机 Isaac Lab `source/isaaclab/isaaclab/managers/reward_manager.py:129–157`。

### 8.3 修改：终止当步的数据流与 -10 惩罚

原始 `isTerminalState()` 在手部任一点低于桌面时设置 `terminalReward=-10`，C++ vector wrapper 将其加到返回奖励上；但 **原 Python Teacher 训练循环随后用奖励信息中的 `reward_sum` 重写 `reward_r[i]`**。该奖励信息在添加 terminalReward 前保存，因此从静态数据流看，额外 `-10` 不会保留到该 Python 训练循环传给 PPO 的奖励中。

当前显式注册 `terminal_reward`，函数返回 `hand_height/step_dt`、配置权重 `-10`，使 RewardManager 最终在高度终止当步确实加 `-10`，不乘普通奖励的 `1/12` 系数。

此外，原 wrapper 先自动 reset，原 Python 再从 `obs_new_r/dis_info/global_state` 重算四个奖励项；终止环境会混用 reset 后几何量与之前保存的 C++ 奖励信息。当前 Isaac Lab 在 reset 前计算 termination 和全部 reward，四个几何项来自终止状态。

所以，当前实现保留了原 C++ 的终止惩罚意图，但并非原完整 Python 训练路径在终止步的逐值复刻。这是依据调用顺序作出的静态结论，本次没有运行两边终止样本验证数值。

证据：`O-Env:1065–1084`；`O-Step:414–429`；`O-Train:591–627、636`；`C-MDP/rewards.py:132–134`；本机 Isaac Lab `source/isaaclab/isaaclab/envs/manager_based_rl_env.py:203–221`。

### 8.4 新增/适配：显式 timeout 和更广的非有限检查

当前训练只注册 `timeout`、`hand_height`、`invalid_state` 三项终止：

- 手部点高度严格 `<0` 的判断保留。
- 非有限判断由原 C++ 的 `obDouble_r_/global_state_` 中 NaN，扩展为实际策略观测、机器人/物体状态及相关接触数据的 NaN/Inf；物理子步中的非有限标志会保留到终止判断。
- 新增环境内 14 s timeout，作为 truncation 交给 RSL-RL 进行价值 bootstrap。原始 C++ 终止函数没有 14 s timeout，而由 Python 外循环限制 70 步并在下一迭代重新采样。

抬升、两指接触、对向接触、保持时间、物体速度或关节速度超阈值均不是当前训练终止条件。

证据：`O-Env:1065–1087`；`O-Train:173、260–275、301`；`C-Cfg:140–156`；`C-MDP/terminations.py:7–33`；`observations.py:819–862`；本机 RSL-RL `algorithms/ppo.py:176–180` 及 Isaac Lab `rsl_rl/vecenv_wrapper.py:161–162`。

## 9. PPO 训练语义修改

| 项目 | 原始有效配置 | 当前有效配置 |
| --- | --- | --- |
| 实现 | 仓库自带 PPO | RSL-RL `OnPolicyRunner` / PPO |
| Actor/Critic 隐藏层 | `[128,128]` | `[256,256,128]` |
| 激活 | LeakyReLU | ELU |
| 观测归一化 | `observe_vision_new()` 返回原字段，不调用观测归一化路径 | Actor、Critic 均启用在线归一化 |
| 初始探索 std | `1.0` | `0.5` |
| std 参数化 | 直接训练 `std` | 训练 `log_std`，取 exp 得到 std |
| std 下限 | 每次 PPO 更新后投影到至少 `0.2` | 当前入口与标准 ActorCritic/PPO 中没有对应下限投影 |
| 每环境 rollout 长度 | 70 步，14 s | 32 步，约 0.533 s |
| 学习 epoch | 4 | 5 |
| mini-batch 数 | 4 | 4 |
| batch 组织 | `shuffle_batch=False`，顺序分批 | 标准 RSL-RL mini-batch generator |
| learning rate | 默认 `5e-4` | `3e-4` |
| value loss coefficient | 默认 `0.5` | `1.0` |
| entropy coefficient | 默认 `0.0` | `0.005` |
| max gradient norm | 默认 `0.5` | `1.0` |
| PPO clip / desired KL | `0.2 / 0.01` | `0.2 / 0.01`，保留 |
| 学习率 schedule | adaptive | adaptive，保留 |

当前 32 步是一次 PPO rollout 的长度，不是抓取回合长度；14 s 回合可能跨越多次 PPO 更新。原始训练每次外层迭代重新生成预抓取状态，这部分调度也与当前不同。

原始检测梯度爆炸后会重新加载已保存模型；当前在非有限观测、奖励、loss 或参数时抛错停止，并在满足保存条件时记录已完成更新，没有沿用自动回滚继续训练的流程。

这些是训练算法和策略输入分布的变化，不是 Isaac Lab 环境 API 更名所必需的同义替换。原始 checkpoint 也不能因动作/观测维度相同而直接复用。

证据：`O-Cfg:121–124`；`O-Train:127–128、177–208、694–705`；`O-PPO:11–40`；原始 `algo/ppo/module.py:100–132`；`O-Vec:183–212`；`C-PPO:7–30`；`C-Scripts/train.py:87–118、150–158`；本机 RSL-RL `modules/actor_critic.py`、`algorithms/ppo.py`。

## 11. 评估、成功定义和尚未迁移的部分

### 11.1 修改/新增：明确区分纯策略与脚本抬升

`play.py` 是 `policy(obs) -> env.step(actions)` 的纯策略播放，不替换机械臂动作，不执行脚本抬升，输出 lift/终止信息，但不据此注册训练成功条件。

`visual_eval.py` 对照原始可视评估流程：14 s 策略抓取后，接 6 s 脚本抬升。机械臂目标从切换时实测 q 向 `theta0=[0,-1.57,1.57,0,1.57,-1.57]` 插值，保留原 80 个源控制步即 16 s 的插值时间尺度；所以 6 s 抬升段结束时只完成这条插值约 37.5%。

当前抬升段手指使用抓取末次策略动作，每 `0.2 s` 按 `q_measured+0.015*a` 更新一次并保持目标；这一段没有使用抓取阶段的 `0.1` 手指动作尺度。该安排保留源抬升时手指目标更新规则；PhysX 动力学和随机延迟仍不同。

成功高度仍为：

```text
top_link_world_z_current - object_root_world_z_at_reset > 0.10 m
```

当前额外要求完整评估序列不中途异常 reset；最后一步正常 timeout 允许完成，关闭窗口导致序列未结束时不计入成功分母。最终使用末帧高度，而不是 `max_lift`，也不附加 grip、good_contact 或 1 秒 hold。输出名为 `scripted_lift_success`，表示“策略抓取 + 脚本抬升”的结果，不是策略自主完成抬升的成功率。

证据：原始 `allegro_teacher/visual_eval.py:207–209、520–533`、`quantitative_eval.py:528–529`；`O-Env:605–608`；`C-Scripts/play.py:61–70`；`visual_eval.py:52–60、74–101、123–165`；`C-MDP/observations.py:899–901`。

### 11.2 未迁移：原始全量定量评估、Student 和真实机器人链路
