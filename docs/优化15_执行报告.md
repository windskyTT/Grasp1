## 五、问题4：Root与Top位置一致性

### 1. 资产与坐标关系

已检查原始物体URDF、Grasp1训练URDF和加载后的USD，覆盖35类不同训练物体：

- Articulation根刚体为bottom，top通过rotation被动转动关节相连。
- 两侧关节锚点的平移均为零，因此关节转动不引入两个link原点之间的固定平移。
- `root_pos_w` 对应根连杆／actor原点；`body_link_pos_w` 对应link原点；二者不能与COM位置混淆。
- 原始成功高度使用top当前位置减Reset root位置，现实现保持该参考方式。

没有修改物体资产、奖励、终止条件或成功判据。

### 2. 实际位置偏差

128环境覆盖全部35类物体，正常运动为128控制步、256物理帧。另检查Reset后，以及受控抬高物体0.20 m后的正常物理帧。

| 阶段 | 最大三维位置偏差 |
| --- | ---: |
| Reset后 | 1.930491 µm |
| 正常运动 | 2.145767 µm |

## 七、问题6：修复成功率统计

原始Teacher的评估统计为 `成功次数 / 评估次数`。并行自动Reset环境改用Wrapper返回的完成信号：

```python
done = dones.bool()
completed_episodes += done.sum()
successful_episodes += (done & teacher_episode["success"].bool()).sum()
success_rate = successful_episodes / completed_episodes
```

不再将成功事件总数除以控制步数。未结束环境的success为真也不计数；每个Episode仅在done时计一次。计数按每次PPO更新的rollout窗口汇总、输出后清零；跨窗口Episode在实际结束的窗口计入。

`completed_episodes=0` 时，终端输出 `None`，Writer跳过成功率标量；完成数和成功数仍可记录为0。

### 实际验证

- 环境2、5按原高度判据成功，计2个完成、2个成功。
- 第一次PPO更新正确输出 `2 / 4 = 0.5`。
- 下一窗口没有完成回合，正确输出 `None`。
- 自动Reset清除了live success，但teacher_episode保存的成功快照没有丢失。
- 同一受控分支执行了两次真实优化器更新；该0.5仅验证统计，不代表策略能力。

## 八、问题7：修复终止当步日志覆盖

### 1. 原因及最终数据流

Isaac Lab 2.3.2 `ManagerBasedRLEnv.step()` 的顺序为：

```text
正常物理子步
→ TerminationManager.compute()
→ RewardManager.compute(step_dt)
→ 对done环境执行_reset_idx()
→ 计算Reset后的观测
→ RslRlVecEnvWrapper返回dones与extras
```

`_reset_idx()` 会重建 `extras["log"]`。因此终止计算阶段写入的逐步日志不能作为唯一的终止结果来源。

最终train.py只读取 `extras["teacher_episode"]` 的Reset前快照，并计算：

```python
completed = sum(done)
successful = sum(done & success)
unsafe = sum(done & unsafe)
timeout = sum(done & timeout)

success_rate = successful / completed
unsafe_rate = unsafe / completed
timeout_rate = timeout / completed
```

三个比率在completed为0时均为None，不写虚假0%；各类标志可以重叠，但总完成回合数只由done计算一次。

`reward`、`opposing`、`lift` 仍按原控制步平均方式统计。没有改变原有PPO更新、奖励统计、checkpoint保存或play.py。

### 2. 环境log不被修改

只生成传给Runner的extras/log副本，从副本中排除旧逐步 `success_rate`、`unsafe_rate`；环境内部字典保持原样，Reset的内部行为也保持原样。

回合计数及三种比率继续使用原metrics和TensorBoard Writer，标签为：

- `Teacher/completed_episodes`、`Teacher/successful_episodes`。
- `Teacher/unsafe_episodes`、`Teacher/timeout_episodes`。
- `Teacher/success_rate`、`Teacher/unsafe_rate`、`Teacher/timeout_rate`。

没有新增日志系统，没有把Reset后的live状态当作终止结果。

### 3. 受控计数与Writer验证

受控16环境依次覆盖2次超时、1次成功、3次unsafe标志，以及1次“成功+unsafe+超时”重叠：

| 指标 | 实际输出 |
| --- | ---: |
| completed_episodes | 7 |
| successful_episodes | 2 |
| unsafe_episodes | 4 |
| timeout_episodes | 3 |
| success_rate | 2/7 = 0.2857142857 |
| unsafe_rate | 4/7 = 0.5714285714 |
| timeout_rate | 3/7 = 0.4285714286 |

三类计数相加为9，但总回合数仍是7；后一个更新窗口completed=0，三种率均为None。

这里unsafe是受控设置的既有sticky标志，用于验证自动Reset和统计路径，**不是4次真实物理失稳**。受控高度同样不计作自主成功。正常1/16/128环境各两次PPO更新通过；受控16环境分支另有两次真实参数更新。
