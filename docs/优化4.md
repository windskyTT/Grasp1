## 4. Phase 1：修正 Observation 22:44 的真实 target error 语义

### 4.1 当前问题

当前动作：

```python
target = current_joint_pos + processed_actions
target = clamp(target, joint_lower, joint_upper)
```

因此实际执行的是：

```text
actual_target = clamp(q + Δq)
```

但是当前 Observation 22:44 仍然读取：

```text
processed_actions
```

未发生 clamp 时：

```text
actual_target - q = processed_actions
```

成立。

发生 clamp 后：

```text
actual_target - q != processed_actions
```

因此 Observation 22:44 在关节边界附近并不表示真实：

```text
target - current
```

这与原 Teacher observation 语义不一致。

### 4.2 修改目标

Observation 22:44 必须变为：

```text
实际发送给 articulation 的 clamped target
-
当前 joint position
```

即：

```text
actual_target_error
```

而不是：

```text
raw processed relative delta
```

### 4.3 推荐实现方式

优先让：

```text
TeacherRelativeJointPositionAction
```

保存当前实际 target。

建议提供显式 property，例如：

```python
@property
def target(self):
    return self._target
```

`apply_actions()` 中：

```python
target = current + processed_actions
target = torch.clamp(target, limits[..., 0], limits[..., 1])
self._target = target
self._asset.set_joint_position_target(target, joint_ids=self._joint_ids)
```

Observation：

```python
target_error = action_term.target - joint_pos
```

不要在 observation 中重新复制一套 clamp 逻辑，避免 action/observation 漂移。

### 4.4 Reset 语义

full reset / partial reset 时必须同步处理 target state。

reset 后：

```text
processed_actions = 0
stored target = 当前 measured joint position
```

从而：

```text
Observation 22:44 = 0
```

不得让 reset 后残留上一 episode target。

### 4.5 Observation 专项测试

至少测试：

```text
A. zero action
B. 非边界 + positive action
C. near upper + positive action
D. near lower + negative action
E. 全22 joints
```

期望：

```text
zero action:
target_error = 0

limit内:
target_error = processed_action

upper clamp:
target_error = upper - q

lower clamp:
target_error = lower - q
```

### 4.6 Phase 1 Gate

必须满足：

```text
[ ] Observation仍为153-D
[ ] 0:22仍为joint_pos
[ ] 22:44为真实clamped_target-current
[ ] unclamped情况下与processed_actions一致
[ ] clamp情况下与实际target一致
[ ] full reset target_error=0
[ ] partial reset selected env target_error=0
[ ] non-reset env状态不被污染
[ ] target outside fraction仍为0
[ ] no NaN/Inf
```

## 7. Evaluate lift 阶段：增加 hand hold A/B 诊断

当前 lift 阶段：

```python
actions = last_grasp_actions.clone()
```

只替换 arm action。

因为 hand action 为 RelativeJointPositionAction，因此相当于：

```text
每个lift step重复最后一次relative hand delta
```

而不是严格保持：

```text
grasp-end hand posture
```

先实现 A/B，不立即替换默认行为。

### Mode A：current-relative-repeat

```text
保持当前 evaluate 行为
```

### Mode B：hold-grasp-posture

抓取结束时保存：

```text
16个Allegro实际joint target
或实际joint position
```

lift 阶段保持固定 hand target，arm 继续执行原 lift trajectory。

比较：

```text
contact retention
multi-finger contact
height gain
source success
strict success
```

如果：

```text
Mode B明显优于Mode A
```

说明当前 evaluate 存在 relative-action confounder。

如果两者都：

```text
0/30
```

则说明抓取本身尚未稳定形成。

## 28. 最终报告必须区分三类结论

最终 `REPORT.md` 中必须分开：

### A. 已证明

例如：

```text
Observation clamp语义已修正
训练管线finite
某阶段source success是多少
某阶段multi-contact是多少
```

### B. 观察趋势

例如：

```text
contact随iteration增加
height gain逐渐上升
policy std逐渐下降
```

### C. 尚不能证明

禁止把以下内容写成确定结论：

```text
100 iteration 0/30 => 算法失败

0/30 => reward错误

0/30 => gamma/lambda错误

0/30 => 必须重写PPO

0/30 => 永远学不会抓取
```

## 29. 最终原则

当前 Grasp1 的重点已经不是：

```text
继续改PhysX性能
继续照抄Dexsuite
继续频繁修改MDP
```

而是：

```text

↓
进行足够长的RL训练
↓
建立分阶段学习曲线
↓
判断是否真正plateau
↓

```

对于当前：

```text
22维动作

```

100 iteration 只能作为：

```text
early diagnostic
```

本轮首要目标是得到可信的：

```text
100
500
1000
2000
5000
10000
20000
```

iteration 对应的：

```text
grasp behavior
contact quality

height gain
lift success
```

学习曲线，而不是继续依赖单个100 iteration checkpoint做算法结论。
