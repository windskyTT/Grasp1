### 关键运行细节

- 动作检查核对已解析关节索引和残差目标公式；UR5 scale=0.005、Allegro scale=0.015。没有改变 delay、PD 或关节限位。
- Observation 按当前 Teacher 的 153 维布局核对，不擅自增加 `joint_vel`、`last_action` 等额外观测；机器人速度、物体 root pose/quaternion/velocity 在状态检查中另行验证。
- 部分重置后，未选中环境的 robot/object root state、joint position/velocity、episode buffer 和按环境排列的 reset 缓冲保持不变；选中环境的 episode counter 和相关速度清零。
- 当前任务的终止项是 timeout、手部高度违规、观测非有限值；没有独立 object-drop 或 success termination。本轮按现有定义测试，没有新增任务语义。
- 256 环境诊断：140 步、53.28 s、512 次回合结束，其中 510 次 timeout、2 次手部高度违规、0 次 invalid observation。
- 运行时机器人各 link 质量范围 0.001–100 kg、物体各 link 质量范围 0.00098–0.24875 kg；质量非负、存在正质量，惯量有限。固定基座/支架也计入机器人 link 范围；这不是实物参数标定证明。

## E. 未解决问题与验证边界

1. **策略效果仍未证实**：本轮仅训练 20 次迭代，ShapeNet 为 0/30；value loss 后期增大，回报未可靠改善。下一步应先约定抓取效果验收阈值，再进行正式训练与多轮评估；不能保证仅延长训练就能解决。
2. 2048 环境已通过短时随机 rollout 和完整单次 PPO 迭代（含优化器更新与 checkpoint 检查）；这验证了本次训练容量，不证明长期 PPO 稳定或策略收敛。
3. 4096 没有实测。按 1024→2048 的采样峰值增量线性估算，4096 约需 8918 MiB，超过 8192 MiB；这只是容量估算，不是实测 OOM。
4. 10 分钟稳定性在 16 个训练槽位上验证；大规模档位各为 70 步计时，不宣称 2048 已通过长时间 PPO 稳定性验收。
5. 机器人 USD 仍有部分空 frame 的 visual-reference 警告。已核对 base、world、tool0、Flange、ee_link 的源 URDF 没有 visual；另有 Fabric 路径警告。实测未因此失败，没有为消除日志而重写资产。
6. 物体 1 个被动关节未配置 actuator，存在 `0 != 1` 提示；保持原被动关节，未锁死物体。初始化有 NumPy 只读数组转 Tensor 警告，本轮没有写入该 CPU 网格数组。
7. 未进行实物参数标定、所有姿态穷举、训练收敛证明或原 C++ Teacher 全链路逐项等价证明；本报告给出本轮实际覆盖范围。

**2048 环境 PPO 容量复核**：1 次完整迭代，143,360 env steps；collection 44.493 s、learning 0.171 s，RSL-RL 记录训练吞吐 3209 env steps/s。场景创建 227.704 s、仿真启动 13.591 s，训练计时 45.97 s。整个进程每秒采样显存，共 296 个样本，采样峰值 5722 MiB；未观察到 OOM。value loss=172.1856、surrogate loss=-0.001142，所有记录标量有限；保存的 `model_0.pt` 中权重及 optimizer 状态共 52 个张量均 finite。训练及 checkpoint 检查均退出 0。

证据：[训练日志](../logs/acceptance/2026-09-29/ppo-capacity-retest.log)、[显存采样](../logs/acceptance/2026-09-29/ppo-capacity-retest-gpu.csv)、[指标与 checkpoint 检查结果](../logs/acceptance/2026-09-29/ppo-capacity-metrics.json)。运行目录为 `logs/rsl_rl/grasp1_ur5_allegro_teacher/2026-09-30_18-41-53_acceptance_capacity2048_retest/`。此前 `ppo-capacity.log` 仅停留在初始化阶段且未留下退出码，不计为通过或 OOM；上述复测完成了完整验证。

**Profile**：256 环境完成 benchmark 后额外采集 5 个 control steps（100 个 physics steps），profile 不计入上表时间。

- Physics step 包装函数占记录 CPU 总时间约 75.94%（包含调用/等待，不等于 CPU 算力占用率）。
- Rewards 约 8.53%，Scene update 约 8.07%，Observation manager 的 compute 包装段约 1.27%；嵌套段不能直接相加当成互斥分类，reward 内也会计算观测。
- GPU kernel 总时长中，`artiSolveInternalConstraintsTGS1T` 约 49.72%，`stepArticulation1TTGS` 约 21.21%，两者合计约 70.93%。主要瓶颈证据指向 PhysX articulation/TGS。
- PPO smoke 中 collection 远大于 learning，也支持优先关注仿真采集。当前任务没有 Camera/RayCaster/FrameTransformer；没有把 GUI 调试吞吐混入 benchmark。
- 静态检查未发现旧 `isaacgym/gymapi/gymtorch` 调用；MDP 中显式 `.cpu()`/`.item()` 集中在 reset/碰撞回退路径；关键点查找仍有逐步名称解析。记录这些现状，但未实施额外优化重构。

证据：[profile trace](../logs/acceptance/2026-09-29/torch-profile.json)（约 110 MiB）、[kernel 汇总](../logs/acceptance/2026-09-29/profile-summary.json)、[性能汇总](../logs/acceptance/2026-09-29/performance-summary.json)。
