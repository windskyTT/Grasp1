## 6. Phase D — MDP、Reward/PPO退化核查（不把脚本成功当学习成功）

### D1. 先判定“迭代越多越差”是否真的存在

- **先搜本地训练日志**，将每个checkpoint附上更新次数、seed、task版本、训练对象、课程、外参、初始TCP和Episode。优化10公开报告PPO=0，不能把原脚本10/10误归为早期PPO成功。
- 有已有真实Policy时，用**训练集单木块**、相同20–50个Reset种子和完全相同物理/外参/MDP，对`model_*.pt`每50或100 updates定期运行确定性推理，记录`successful/attempted`、0.10m lift、1.0s hold、time-to-success、unsafe/timeout/drop/invalid reset。随机推理另列，不与确定性混算。
- 若没有真实Policy：直接标记`policy_regression_not_testable_yet`，完成物理/任务安全后运行真实短PPO再作对照；不能编造成功率下降原因。

### D2. Reward、探索噪声及学习过程审计

对`full_grasp_rewards.py`和`full_grasp_metrics.py`做**真实轨迹的总回报比较**：

1. 比较轨迹A（真实完成Lift/Hold，成功终止）与轨迹B（仅保持接近/夹持/高度附近刷持续Reward、没有成功），按**真实step_dt、gamma**积分。若B比A好，重新设计奖励或阶段收益，使有效完成优于刷分；保持事件奖励只发生一次，不再重复按dt放大。
2. 保持夹持/抬升/保持信号必须与物理成功条件一致，不靠瞬时力阈值或弹飞获得高回报；检查真实指尖法向/摩擦、相向法向、物桌分离和相对速度。
3. 检查`min_action_std=0.2`下的训练随机动作幅度，区分actor均值确定性推理和采样动作；检查动作被`clip_actions=1.0`及关节限位饱和的频率。调整噪声/学习率/熵/KL时做少变量A/B对照，**不能只因success下降就武断降低LR**。
4. 保存PPO的`approx KL/value loss/entropy/action std/reward terms/fps/显存`及各失败分类与Reset成功率。只有真实数据支持，才归因策略退化、分布漂移或Reward hack。
5. 新资产外参/TCP/Reset/奖励变化必须形成新的`mount_semantics_version`、`tcp_semantics_version`、`observation_semantics_version`、`action_semantics_version`、`reward_semantics_version`及schema签名；必要时新Task ID `Grasp1-UR5-Allegro-GraspTrain-v3`，单独实验目录，不偷换已有v2权重。若v2必须变动，也必须显式升级版本号和迁移文档。优先复用IsaacLab Manager-Based及标准RSL-RL，不造第二套PPO。

### D3. 短PPO训练（仅通过物理安全Gate后）

- 先选已完成脚本/真实安全验证的**训练集木块C1**，128或更少env起步（受3070Ti 8GB实测约束），`--headless`真实训练；建议100→500→1000 updates分阶段，每阶段保留成功率与明确的失败原因。
- 固定物体和Reset分布，不能在Checkpoint比较中偷偷改变初始高度/装配，训练期任何课程升级必须记录时间点并使用**独立固定测试协议**重测。
- 每50 updates保存至少一个带契约的Checkpoint；训练失败时保留现场与可恢复模型。选择`best.pt`基于固定训练集协议的**真实自主抓取成功率**，不是只看总Reward，更不能直接用最后更新的`last.pt`。
- 优先实证：策略学会抓握+上抬+保持，且成功率明显优于随机动作；只有短期学习确有进展，才批准8–10小时长训。

**Gate D**：至少一个真实训练`*.pt`、可核对PPO update数、固定协议Policy成功率和随更新变化曲线。未成功则说明具体阻断点；严禁以脚本`10/10`代替。
