已知事实（以 `docs/优化17_问题.md` 为准）：最近一次 20,001 次 PPO 更新后，7 个候选 checkpoint 对 35 物体 × 3 次评估共 **0/735 成功**，原 GUI 评估 **0/6**；733 次完成抓取的尝试中，抓取末尾 0–1 个指尖有效接触占 **90.45%**，仅 **2/733** 次满足现有对向接触诊断；抬臂结束前 **704/733** 次无指尖接触。`model_6860.pt` 是已保存迭代中 Train/mean_reward 最高的候选，`model_11480.pt` 出现本次最大最终高度差 `0.093139052 m`，二者均**不是已验证成功模型**。不得将 GUI 姿态异常直接等同于 checkpoint 加载错误、关节顺序错误，或将这些数据误写成所有权重必然失败。

## 4. 必须依次执行的审查与修复

### P0-A：精确定位“异常姿态”出现的阶段

在**同一 checkpoint、同一物体、同一 Reset 物理状态**下分别执行纯策略 `play.py` 与 `visual_eval.py`；对比 `model_6860.pt`、`model_11480.pt`。避免只用相同 seed 推断多环境实际 Reset 状态完全相同；若要对比，利用现有程序结构在内存中保存/恢复真实关节、物体根/关节、必要观测及策略状态，不创建状态文件。

逐阶段至少检查 `reset`、抓取步 `0/420/839`、抬臂起始 `840`、抬臂中段及末步：

1. 手掌/腕/TCP 与 `Object/top` 的世界位姿和相对位姿、手掌接近轴、物体表面可见点云中心；四指尖到物体的位置和距离。
2. 22 维原始策略输出、动作处理后的增量、发送的目标 `q_target`、实测 `q`、`qd`、位置误差、关节目标限位饱和次数；特别记录末次手指动作与抬臂阶段累计变化。
3. 13 个奖励接触槽的冲量/接触标志，以及四指尖分别来自 `distal`/`fixed tip` 的接触法向和摩擦；识别拇指与其他手指是否对向、在哪个具体控制步失去接触。
4. `dones`、`hand_height`、`invalid`、`timeout` 与独立抬升高度，排除跨回合自动 Reset 拼接。

**先输出判断：**异常在 Reset 初态、PPO 抓取过程、切换抬臂瞬间、抬臂持续执行阶段中的哪一段首次出现；写明证据。不要直接因为两张不同相机视角/时刻的照片而旋转机器人根、手掌或更换关节映射。

### P0-B：重点检查 `visual_eval.py` 的“末次手指动作”时间适配

当前 `visual_eval.py` 在抬臂阶段每个 60 Hz 控制步重复 `final_actions`，而 `TeacherRelativeJointPositionAction.process_actions()` 每次重新计算 `q_measured + scaled_action`。原始 RaiSim 只在 5 Hz 下重复末次动作 30 次，并使用 `finger_action_std=0.015`；当前抓取控制的手指单步系数为 `0.1`，抬臂期间执行 360 次。**这是需要量化的动作语义差异，不可未经试验直接断定全部失效均由它引起。**

用固定 Reset 快照进行 A/B：

- A：原样连续重放最后一帧相对动作。
- B：仅在诊断分支中冻结切换时实测手指绝对目标，保持脚本 UR5 插值不变。
- 必要时 C：按原始 5 Hz 源动作语义作具有明确数学依据的时间适配，记录抬臂 6 秒的各关节实际目标和轨迹；不得把“每 60 Hz 重复 0.1 的相对增量”误称为源等价。

比较相同物体的抬臂阶段指尖接触保持、手指角度漂移、目标饱和和物体高度。若确认原样重复导致非原始的快速合拢/松脱，**只在已有 `visual_eval.py` 中实现最小、可解释的抬臂阶段适配**；不能改变训练时 `ALLEGRO_ACTION_SCALE=0.1`，不能偷换成功判据，也不能直接把“冻结手指”作为原始源码的等价实现。若源等价适配不可证实，保留诊断结论并标为 `UNVERIFIED`。

### P1-A：核对 Reset 预抓取坐标系与原始碰撞检查

逐式核对 `events.py` 的 `_sample_object_pose()`、`_visible_points()`、`_solve_pregrasp()`、`reset_teacher()` 和 `geometry.py` 的方向/旋转/IK/抓取中心：

- 源工作区经过当前机器人底座变换后的物体位置、yaw、可见点云、相机位置是否正确；`top=False` 时方向是否一致。
- 源 `HAND_CENTER=(-0.0091,0,-0.095)` 的 **Reset 构造式与观测定义是不同用途**；不能误把其他课程的 `GRASP_TCP_OFFSET` 当成当前 Teacher 手掌安装偏移。逐项验证 wrist/tool/flange/hand 的正逆变换、IK 目标与 FK 世界位姿、实际预抓取距离 `0.25m` 以及物体与桌面 `2mm` 初始间隙。
- 对照 `docs/优化11_执行报告.md` 和 `docs/优化12_执行报告.md`：先前已验证源/当前 URDF 的共同关节、法兰→手掌固定连接及 Mesh 局部偏移基本一致；**无数值证据禁止随意加 90°/180° 旋转或整体改 base/root 安装**。
- 还原历史事实：优化14保留了 IK、限位、最多 32 轮重采样、`sim.forward()` 和 Reset 隔离；但原始源码的 **零动作后的初始化接触检查、同物体无碰撞候选替换、固定回退**未迁移；优化15只是取消了迁移要求，并未实现它们。

先用 1/16/128 环境的真实初始接触、穿透/碰撞对及关节 FK 数据确认该差异是否影响姿态。**若存在可靠的 Isaac Sim 5.1 / PhysX API，可在不额外推进整个并行环境物理时间、不污染其他 env 的前提下实现与原始判据可证明一致的最小碰撞检查及原始回退；否则不得借 `sim.forward()` 后的旧 ContactSensor 值冒充新接触结果，不得发明 AABB/距离阈值替代源碰撞筛选。标记 `BLOCKED/ADAPTED`，保留现有可运行 Reset。**

### P1-B：检查 PhysX 接触与观测/奖励的关联

验证原始 13 个接触槽映射顺序，特别是 USD `fixed tip` 与末端连杆归并、拇指槽，以及碰撞对 `Object/top`、`Object/bottom`、`Table` 的过滤和 frame 对齐。给出相同真实接触事件下 `TeacherRewardState`、153 维观测中的 `44:57`/`57:70`、17 项奖励中接触相关项的一致性；不能把诊断的 `1N` 指尖接触阈值当成奖励的 `0.01 N·s` 冲量阈值。

RaiSim 原源码是逐接触点过滤 `|J|<0.001 N·s`，PhysX 法向接触和 friction patch 不具有已验证的一一对应。允许标注 `ADAPTED`，**禁止直接对聚合冲量套用该阈值冒充等价实现**，也不允许只为让日志显示“对向接触”而重写奖励或接触法向。

### P1-C：验证物理控制链路，而非简单调大训练次数

单关节、零动作、固定小动作和合理接触下检查 UR5/Allegro：`q_target`/`q`/`qd`、饱和与越限、实际驱动响应和非预期碰撞。原始 `simulation_dt=0.01`、`control_dt=0.2`、`finger_action_std=0.015`、`rot_action_std=0.005`；当前是 120 Hz PhysX/60 Hz Policy、UR5 `0.00125`/步、Allegro `0.1`/步。**只描述数值差异及实测后果，不改变锁定参数**。确认在抓取开始前已有碰撞还是执行过程中才接触丢失。

原始 `train.py` 的 `reward_r.clip(min=-2.0)` 未赋值，NumPy `clip` 并未就地修改原数组；**不得把它误判为 Grasp1 缺失的有效奖励裁剪并新增 `reward.clamp_min(-2)`**。PPO 探索噪声上升、价值损失尖峰属于次级线索；先排除物理/观测/动作问题，再建议改变 PPO 参数，而且本任务不得擅自修改 PPO 超参数。

## 5. 最小修改策略与验收

只修复有明确代码证据、可用控制变量证明的缺陷。优先范围是已有 `visual_eval.py` 中抬臂动作处理，以及经验证有误的 `mdp/events.py`、`mdp/geometry.py`、`mdp/observations.py`、`mdp/actions.py` 的 UR5 专属逻辑。没有证据的模块不修改。每个修改都给出“原始源实现 → 当前代码 → 已复现差异 → 最小修复 → 修复后数据”。

验收顺序：

1. 先给出修改前 A/B 与各阶段诊断，确认问题首发阶段；固定同一 Reset 状态，比较修改前后，不能用不同随机物体或不同初态混比。
2. 运行 1/16/128 环境 Reset、零动作、固定动作；检查初始接触、FK/IK、`env_origins`、关节顺序、动作目标和 Reset 隔离。无 NaN/Inf，异常不允许被静默吞掉。
3. 验证训练仍为 153D 观测/22D 动作、840 Env Steps/14s、17项原始奖励与终止语义；在现有 `train.py` 完成 **2 次真实 PPO 更新**（可用原有 `--no_log` 选项，避免创建训练文件）。
4. 用**兼容** checkpoint 分别运行现有 `play.py` 的确定性纯策略和 `visual_eval.py` 的 PPO 抓取+脚本抬臂 GUI；对既有 `model_6860.pt`/`model_11480.pt` 做固定条件的回归。若训练 MDP 已改变，不得硬加载旧 checkpoint，须明确报告需要重新训练。
5. 输出至少：抓取末尾四指尖接触分布、拇指+其他手指对向接触率、抬臂末端接触保持率、末端高度差与严格成功率 `top_z_current-root_z_reset>0.10m`、中途 Reset 数、手指目标限位饱和及实际速度峰值。测试没有出现成功就如实写 `0/N`，不得报告“已经学会抓取”。
6. 对每项结果使用 `PASS / FAIL / ADAPTED / BLOCKED / UNVERIFIED / NOT RUN`，给出实际运行命令、checkpoint 路径/契约、物体、seed、环境数、完整阶段和样本分母。最终只在终端汇报修改过的现有文件、证据、仍需长训的问题；不得额外创建报告文件。

**成功判定**：既修复经证明的时间/坐标/接触实现偏差，又能够用相同初态 A/B 指标证明改进；不能要求两次 PPO 更新就必须出现成功抓取。若实测说明 checkpoint 在抓取阶段已经没有可靠多指接触，则报告“旧权重不具备成功抓取能力”，给出重新训练前的明确条件，而不是靠 GUI 回放修正伪装成策略已收敛。
