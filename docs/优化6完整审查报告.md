## 3. 逐问题审查

### P0-01｜零动作高速尖峰未修复：严重阻断

**既有证据**：[`summary.json`](https://github.com/windskyTT/Grasp1/blob/c280cebf54ae89677b77b3c8313ed5472620151c/logs/acceptance/optimization6/summary.json)、[`diagnosis/peak_case.json`](https://github.com/windskyTT/Grasp1/blob/c280cebf54ae89677b77b3c8313ed5472620151c/logs/acceptance/optimization6/diagnosis/peak_case.json)、[`training_gate.json`](https://github.com/windskyTT/Grasp1/blob/c280cebf54ae89677b77b3c8313ed5472620151c/logs/acceptance/optimization6/training_gate.json)。

| 字段 | 实际值 |
|---|---:|
| 配置 | D4 / 10秒 / 16环境 / zero action |
| 物体、环境 | `wood_block_oriented`，env_id=7 |
| 关节 | Allegro `joint_15_0` |
| 发生时刻 | 第892物理步，7.43333秒 |
| 实测速度 | **112.90218 rad/s** |
| 关节目标 | −0.16199999 rad |
| 关节实测位置 | −0.17644021 rad |
| 相对目标误差 | **0.01444022 rad** |
| 同一环境记录的接触峰值 | 53.9106 N |
| 估算的隐式PD力矩 | 0.7 N·m，**不是**PhysX真实驱动力矩的直接测量 |
| 目标是否跨子步变化 | **否**，缓存目标保持一致 |

**结论**：`target`在位置限位内，不能保证关节实际状态在限位内；目标clamp也不构成速度硬约束。该事件在**零动作**下发生，说明不能只把优化5的Gaussian原始动作幅度视为唯一原因。独立物理轨迹复现了尖峰，但**未定位根因**。

更重要的是，它不是只有D4才可能发生。D2/T10随机动作峰值 **76.9241 rad/s**，D2/T10零动作37.8994rad/s，D4/T4零动作23.9431rad/s；这些都显著高于现有Allegro配置的7rad/s参考速度值（`velocity_limit_sim`并非刚性实测速度裁剪）。

**优先排查建议**：

1. 用现有`zero_physics_trace.pt`复现第887–897步，逐物理步记录**实际关节位置与PhysX reported velocity**、驱动目标、驱动设置、限位接触和solver冲量；额外计算`(q[t]-q[t-1])/dt`与reported qvel的差异，用来分析约束修正和数据时序，不能简单假设二者恒等。
2. 对该手指的相邻碰撞几何、关节轴/限位、USD构型、PhysX接触过滤、驱动stiffness/damping/effort限制进行逐项检查；先测试**无物体接触**、桌面接触和单体接触三组，判断是否为指尖几何/关节限位接触耦合。
3. 在物体质量/惯量、armature=0.1、机器人solver与自碰撞保持不变时单独复现；若确认接触耦合，再分别做solver或armature的独立A/B，**不得一次改多个值后宣称找到根因**。
4. 监控至少`peak |qvel|`、实际`q`限位偏离、`target`限位、接触脉冲、effort估计、是否可复现，以及事件发生的env/物体/物理步。
5. 物理Gate要求**零动作场景无不可接受的关节速度和位置越界**，并为出现接触时的尖峰建立更合理的阈值与持续时间统计；`100rad/s`仅是本轮工程停止线，不是安全阈值。

**避免的误判**：该尖峰与关节下限附近接触同时出现，不等于已证明是目标缓存错误、PD过硬或armature单独造成的；既有实验明确显示子步目标不变。

### P1-02｜评估参考对象刚体不一致，影响与源代码的可比性

原始[`RobustDexGrasp/Environment.hpp`](https://github.com/zdchan/RobustDexGrasp/blob/main/raisimGymTorch/raisimGymTorch/env/envs/allegro_teacher/Environment.hpp)读取`affordance_id = getBodyIdx("top")`，`Obj_Position`及`global_state[:,107]`高度对应的是**top**刚体。当前Grasp1对象被动articulation的`body_names`是`["bottom", "top"]`，URDF亦规定`bottom`是父连杆（如[`wood_block_oriented.urdf`](https://github.com/windskyTT/Grasp1/blob/c280cebf54ae89677b77b3c8313ed5472620151c/assets/objects/new_training_set/wood_block_oriented/wood_block_oriented.urdf)）。

而优化6的[`evaluate.py`](https://github.com/windskyTT/Grasp1/blob/c280cebf54ae89677b77b3c8313ed5472620151c/scripts/rsl_rl/evaluate.py#L399-L410)及[`grasp_diagnostics.py`](https://github.com/windskyTT/Grasp1/blob/c280cebf54ae89677b77b3c8313ed5472620151c/scripts/rsl_rl/grasp_diagnostics.py#L271-L315)使用`object.data.root_pos_w`/`root_pose_w`计算初始和末端高度、相对位姿与5秒稳定性，而不是显式使用`object.data.body_link_pose_w[:, object_top]`。

**确定的缺陷是参考刚体语义不严格一致**。由于原始对象关节只允许约0–0.001rad旋转，两个刚体的参考原点又可能接近，很多正常状态下二者的Z差或许很小；因此不能在没有逐步测量的情况下宣称成功率已被实质扭曲。PhysX约束失稳时差异可能放大。

**建议**：同时输出`root/bottom/top`三组世界位姿，用同一批40秒轨迹比较高度差及成功分类差异；正式原始高度指标以**top**的世界Z为准，工程上另存root和bottom供诊断；稳定相对位姿也应使用夹持对象top并在结果中记录参考刚体。

### P1-03｜物理峰值包含已失败并自动重置的环境

[`evaluate.py`](https://github.com/windskyTT/Grasp1/blob/c280cebf54ae89677b77b3c8313ed5472620151c/scripts/rsl_rl/evaluate.py#L426-L498)在trial失败后使`active=False`并将动作置零，但整个并行环境仍继续调用`env.step()`。[`PhysicsDiagnostics.update`](https://github.com/windskyTT/Grasp1/blob/c280cebf54ae89677b77b3c8313ed5472620151c/scripts/rsl_rl/grasp_diagnostics.py#L193-L225)却对所有env的`q/v/force`取峰值，并未使用`active`掩码，也没有区分不同的自动reset episode。

因此正式40秒评估时，一个已经失败的环境后续重新初始化所产生的碰撞峰值，仍可进入全局`physics.contact_force_peak_N`或`hand_velocity_peak`，而这不是原始trial期间的物理响应。

**建议**：诊断分别报告`active_trial_peak`、`failed_before_reset_peak`及`all_scene_peak`，并在自动重置边界冻结逐trial峰值；不能把未经筛选的全场景峰值作为成功策略的物理质量证据。修复后用强制终止、自动reset再制造高峰的单元测试确认active_trial统计不污染。

### P1-04｜20+20秒协议是“配置正确”，尚不是“评估验证通过”

源码默认确为`grasp_duration_s=20`、`lift_duration_s=20`、`lift_ramp_duration_s=16`，计算D2为1200+1200/960步、D4为600+600/480步；任务episode增至40秒加两步，边界检查正确。

但[`evaluation_entry_checks.json`](https://github.com/windskyTT/Grasp1/blob/c280cebf54ae89677b77b3c8313ed5472620151c/logs/acceptance/optimization6/evaluation_entry_checks.json)真实运行的只是**0.2秒抓取+0.2秒抬升**（D2每段12步；D4每段6步）；没有完整的40秒策略执行或40秒期间的实时对象滑落、接触与终止行为记录。

**建议**：物理Gate修复后，先用1对象×1轮跑40秒端到端（包括提前失败注入），再30对象×3轮正式评估；必须逐物体报告成功率、失败原因、长时间动作饱和、真实高度和完整连续轨迹。

### P1-05｜源Reward的接触冲量仍存在结构性近似

优化6在[`source_audit.md`](https://github.com/windskyTT/Grasp1/blob/c280cebf54ae89677b77b3c8313ed5472620151c/logs/acceptance/optimization6/source_audit.md)已正确指出：RaiSim在世界坐标对`impulses_r_af_xy`取XY向量模、`impulses_r_af_z`取有符号Z值；Grasp1在[`mdp/runtime.py`](https://github.com/windskyTT/Grasp1/blob/c280cebf54ae89677b77b3c8313ed5472620151c/source/Grasp1/Grasp1/tasks/manager_based/grasp1/mdp/runtime.py#L92-L121)使用接触法向/摩擦向量的模×physics_dt。**世界XY/Z不是接触局部切向/法向**，这两套奖励对于倾斜表面尤其不等价。

转换N到N·s的维度解释并不能证明原始接触方向、阈值与时间采样等价。若正常样本源奖励本应鼓励某方向的接触冲量，却被误当作另一种量，策略的抓取动作可能受影响。**当前尚无对照数据证明它是主要训练失败原因。**

**建议**：单独对固定接触法向方向与斜面接触做世界坐标变换及奖项值单测；保持当前奖励作为baseline，建立worldXY/worldZ实现作受控A/B，不要混入D2/D4主对照。

### P1-06｜Checkpoint缺少训练控制语义兼容验证

`train.py`在CLI覆盖decimation/episode并同步时间参数后允许`runner.load(resume_path)`；`evaluate.py`也允许以`--decimation=4`加载D2或优化5旧checkpoint，当前未看到对保存的`env.yaml`、agent配置和动作目标生成版本进行严格兼容校验。

虽然网络维度仍为153/22，**相同形状不代表相同的控制频率、Observation时间语义、gamma/lambda或动作执行律**。这不会必然触发加载错误，却可能使对照结果失去可解释性。

**建议**：checkpoint元数据写入`physics_dt/decimation/control_dt/episode/action_semantics_version/reward_semantics_version/obs_version`；正式训练resume时强制完全一致；诊断性跨配置play/evaluate需要`--allow_mismatched_checkpoint`显式标注，结果JSON保存差异与警告。

### P1-07｜Gate决策对安全候选和失败候选缺少分层

既有要求“物理Gate失败则停止正式训练”被正确执行；这是优点而非违规。但现在`D4_T10 zero`单个失败让**所有E1–E4均为零更新**，无法区分以下问题：是D4引入不稳定，还是“超过4秒”暴露已有短回合未触发的接触，或是共同的模型/PD病灶。

建议将门槛划分为：A）**全局硬错误**（如状态NaN、明显危险/不可接受物理失控，停止全部候选）；B）**候选专项Gate**（特定D4/T10下峰值超线，冻结该候选，其他候选可在相同或更严格的安全标准下继续诊断）；C）**共性问题**（D2/T10的76.9rad/s也值得诊断，不应因为低于100就被宣称安全）。任何正式训练仍必须在相关候选的安全Gate实际通过之后启动。

### P2-01｜“论文级稳定”仅为工程代理判据

`grasp_diagnostics.py`用最后5秒的高度持续>0.1m、每策略步检测到至少一处接触、相对位移≤2cm、相对转角≤0.2rad和未终止共同判定`paper_stable_success`。该设计有助于排除末帧偶然抬起，但**2cm与0.2rad并非论文公布的严格阈值**；不同物体的可接受滑移也不同。还有一个重要细节：连续接触只按策略频率采样，未必证明每个物理子步持续接触或形成有效力闭合。

建议把名字改成`engineering_stable_success`或明确写明“论文目标的工程近似”，在正式报告中保留高度、时间、位姿与接触各子判定，单独展示并通过真实成功/失败样本标定阈值。

### P2-02｜旧物理模型问题未因优化6消失

物体的近固定`bottom/top`被动旋转关节采用零PD、`armature=0.1`；UR5-Allegro机器人自碰撞关闭、隐式PD和PhysX TGS保持不变。这些保证了单变量物理A/B的可比性，但**没有证明它们与原始RaiSim的动力学等价**。尤其armature对轻质量bottom的动力学影响、7rad/s速度配置与实测速度尖峰的矛盾、关节位置限位附近的解算状态都需要专项实验。

### P2-03｜PPO固定学习率与后期Critic失稳仍是旧遗留

优化6只有**两次更新**的接口smoke，Critic指标有限只能说明程序可运行。优化5在2000次时已出现显著Value loss增长，当前仍使用fixed 5e−4、minimum std0.2、Gaussian不裁剪。后两项与源训练语义一致，不应草率撤销；fixed vs adaptive应在物理Gate通过后独立对照。也要报告GAE与rollout采样时长变化：同为32步，D2=0.5333s，D4=1.0667s，不能单靠时间指数换算就视为同一个PPO实验。

### P2-04｜次要可维护性与参数检查

- `evaluate.py`用`assert`要求`--paper_stability`与20+20秒配对；建议使用`parser.error()`，避免在生产命令行中出现裸断言失败。
- 当前未看到对`lift_ramp_duration_s <= lift_duration_s`的显式检验；用户误传更长Ramp会导致在评估结束前从未达到目标UR5姿态。
- 训练配置注释仍有“32步与240步episode”以及“5Hz→60Hz”等旧文案；动态D4/10秒后易误导。建议统一以真实控制周期表述。
- 结果中的`strict_success`实际是“未提前终止＋末端高度”，不是5秒稳定夹持，推荐主命名`active_height_success`，将历史别名作为兼容输出。
- 提交包含大量验收临时文件与历史日志，可保留必要机器可读证据，但应注意未来Git仓库膨胀、二进制/LFS可用性与可复现性；不要删除现有用户日志。

## 5. 建议修复顺序与各阶段验收门槛

### A. 物理尖峰根因定位（必须先做）

**先只读复现，固定**物体列表、seed、PD、solver、armature、随机动作集和环境数，确定异常是否来源于接触与位置限位求解。新增每个PhysX子步的最小追踪项：`q、qvel、(Δq/dt)、target、target−q、contact body pair、法向/摩擦、effort估计、object q/qvel、solver与limit flags`；给出至少一个可复现的“最小单对象/单环境”测试。如果没有接触时仍出现速度尖峰，优先核对USD articulation/驱动状态；如果仅特定指节与物体几何接触时出现，则定位相应碰撞和限位。

**Gate A**：对zero/random/极端但合法目标的D2/D4逐物理步测试不得有未解释的速度和关节位置尖峰；物体被动关节与finite保持可控。必要时先对全部候选暂停训练。

### B. 修复评估计量与诊断口径

实施top/body高度对照及active-trial物理峰值隔离；为每个trial保存“首次失败前最后有效姿态”；checkpoint与训练控制配置进行严格兼容检测。另将`paper_stable_success`阈值标注工程代理，补充Ramp参数校验。

**Gate B**：通过合成的bottom/top高度不同场景、提前终止再自动reset场景、30环境重复副本场景；所有指标可重建且分母正确。

### C. 重新执行E1–E4受控筛查与训练

| 组 | decimation | episode | 优先用途 |
|---|---:|---:|---|
| E1 | 2 | 4s | 修复后短时基准 |
| E2 | 2 | 10s | 单独测试延长Episode |
| E3 | 4 | 4s | 单独测试降低策略频率 |
| E4 | 4 | 10s | 测试30Hz+10s组合 |

在物理Gate通过后，每个候选从头训练并按100→500→1000→2000更新检查：Value loss的阶段均值/峰值、Reward项、raw动作、目标饱和、关节速度/接触峰值、实际抓取接触覆盖、多指接触、4–10秒是否提升夹持质量。**比较时同时报告采样的策略步数、每环境模拟物理时间、实际墙钟和GPU小时有效抓取指标**。最终候选多seed复验，再决定是否更改训练默认值。

### D. 真实执行20秒抓取＋20秒抬升

1. 先使用**同一个安全检查点**完成1物体×1轮40秒全程烟测，验证超时、重复reset、Grip→Lift transition、16秒Ramp及轨迹保存。
2. 使用30个ShapeNet对象×每物体至少3轮、Mode A、**20+20＋16秒Ramp**进行主源时长评估。保存top高度与失败原因。
3. 独立执行**20+20＋14秒Ramp**和后5秒稳定保持工程代理协议；Mode B仅作诊断。
4. 各配置报告`source_height_success`、`active_height_success`、`engineering_stable_success`，明确训练4/10秒与长时评估40秒之间的分布外风险。
