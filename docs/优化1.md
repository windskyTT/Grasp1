# 1. 本次任务目标

在保持当前 Teacher 行为、观测、奖励、动作、reset、termination 和训练语义不变的前提下，对以下六类重复计算进行优化：

```text
1. 消除 affordance_reward 对完整 policy observation 的重复计算

2. 将 hand / arm / object 的 body ID
   从每 step find_bodies()
   改为初始化阶段一次解析并缓存

3. 同一个 control step 内，
   hand-object / hand-table / arm contact 数据只整理一次，
   多个 reward term 共用

4. 同一个 control step 内，
   hand_keypoints
   arm_keypoints
   affordance nearest vectors
   等共享几何量只计算一次

5. 检查 weight=0 的 push_reward 是否仍进入 RewardManager 运行路径，
   如果可以安全禁用，则避免无意义计算

6. 优化 reset/startup 阶段的 CPU 文件读取、metadata lookup、
   object mesh lookup 和重复名称解析
```

目标是：

```text
降低 Reward / Observation / Scene 后处理开销
提高 env steps/s
降低单次 PPO rollout collection 时间
```

不得以改变任务定义的方式获得性能提升。

# 5. 优化任务 1：
# 消除 affordance_reward 的完整 Observation 重算

重点检查：

```text
source/Grasp1/Grasp1/tasks/manager_based/grasp1/mdp/rewards.py
```

当前需要重点检查类似：

```python
env.observation_manager.compute_group("policy")
```

出现在：

```text
affordance_reward
```

中的情况。

当前问题：

```text
RewardManager
    ↓
affordance_reward
    ↓
compute_group("policy")
    ↓
完整 TeacherObservation 重新执行
```

而之后：

```text
ObservationManager
```

还会正式计算一次 policy observation。

这可能导致一个 control step 中至少重复执行：

```text
hand keypoints
arm keypoints
contact observation
wrist transform
torch.cdist
nearest affordance point
quaternion transform
```

要求：

1. 不允许 `affordance_reward()` 为了读取 102:153 再调用完整：

```python
observation_manager.compute_group("policy")
```

2. 应建立共享的：

```text
nearest affordance vectors
```

或其等价中间结果。

3. Reward 和 Observation 必须使用同一份当前-step 数据。

4. 不允许 Reward 使用上一个 control step 的 stale 数据。

5. 必须明确缓存生命周期。

例如概念上：

```text
current control step
      ↓
compute shared Teacher runtime features
      ↓
├── observation
└── reward
```

具体实现方式由你根据 Isaac Lab 2.3.2 Manager 生命周期决定。

不得因为缓存顺序错误造成：

```text
reward(t) 使用 observation(t-1)
```

# 7. 优化任务 3：
# Contact Tensor 单 step 共用

重点检查：

```text
mdp/rewards.py
mdp/observations.py
```

当前 Teacher 使用大量 filtered ContactSensor。

包括：

```text
13 hand → affordance/object
13 hand → table
6 arm → object/table
```

当前多个 reward term 会重复执行类似：

```text
读取 ContactSensor
读取 force_matrix_w
读取 friction_forces_w
sum
vector norm
乘 physics_dt
stack
threshold
```

例如需要检查：

```text
affordance_contact_reward
affordance_impulse_reward
push_reward

table_contact_reward
table_impulse_reward

arm_contact_reward
arm_impulse_reward
arm_collision_reward
```

目标：

同一个 control step 内，对每类 contact 数据只完成一次基础整理。

概念上：

```text
Hand/Object contact cache
    ↓
total impulse
tangential impulse
normal impulse
contact flags

Hand/Table contact cache
    ↓
total impulse
tangential impulse
normal impulse
contact flags

Arm contact cache
    ↓
total impulse
...
```

然后不同 reward term 直接读取。

不要出现：

```text
affordance_contact_reward
→ 遍历13个sensor

affordance_impulse_reward
→ 再遍历13个sensor

push_reward
→ 再遍历13个sensor
```

要求：

```text
不能改变 contact threshold
不能改变 force → impulse 的计算公式
不能改变 friction/normal 含义
不能改变 reward 数值
```

# 11. 不要过度缓存

性能优化不得导致：

```text
VRAM 显著暴涨
复杂的跨 Manager 隐式状态
难以确认缓存step是否过期
partial reset错误
```

对于 2048 env，任何额外缓存都必须评估 shape。

例如：

```text
[N,17,200,3]
```

这种巨型中间 Tensor 不应长期保存，除非证明有必要。

优先缓存：

```text
最终或中等大小的共享结果
```

例如：

```text
[N,17,3]
[N,17]
[N,13]
```

而不是完整 pairwise difference tensor。

# 12. GPU / CPU 原则

runtime 热路径：

```text
action
observation
reward
termination
contact processing
keypoint transform
```

原则上保持：

```text
CUDA torch.Tensor
```

搜索并记录：

```text
.cpu()
.numpy()
.item()
tolist()
```

如果出现在每-step runtime 路径：

必须判断是否可消除。

注意：

```text
.item()
```

可能触发 GPU synchronization。

不要为了日志或 Python 分支在每一步频繁同步 GPU。

但不要机械删除所有 `.item()`：

```text
startup
debug
error reporting
final statistics
```

可以保留。

# 23. 最重要的原则

```text

把任务变简单。
```

而是：

```text
保持 RobustDexGrasp Teacher → IsaacLab 当前迁移语义
                 +
消除明确重复计算
                 +
提高 rollout throughput
```

优化优先级：

```text
消除重复计算
>
缓存静态索引
>
共享 per-step runtime features
>
减少 CPU/GPU synchronization
>
优化 reset
>
修改物理配置
```

本任务停止在：

```text
安全的软件层性能优化
```

不要进入会改变训练任务物理语义的优化阶段。
