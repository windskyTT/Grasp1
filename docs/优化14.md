## 问题3：训练过程中首次异常会中断整个 PPO

解决方案：删除全局停训机制，保留单环境终止

对照原始 RobustDexGrasp 的 `train.py` 和 `Environment.hpp`，可以确认：

**原始 RobustDexGrasp 不会因为一个环境出现普通碰撞或异常终止，就停止整个 PPO 训练。**

原始训练代码是：

```python
reward_r, _, dones = env.step(
    action_r.astype('float32'),
    action_l.astype('float32')
)

ppo_r.step(
    value_obs=obs_r,
    rews=reward_r,
    dones=dones
)
```

原始 `Environment.hpp::isTerminalState()` 主要检查手部关键点低于地面及观测中的 NaN，并返回对应环境的终止状态。

**因此，Grasp1 应保留 Isaac Lab/RSL-RL 原生的逐环境 `done → reset → 继续采样` 流程，不应额外增加全局停训条件。**

### 1. 需要修改的位置

文件：

```text
/home/windsky/project/Grasp1/scripts/rsl_rl/train.py
```

找到：

```python
if raw._teacher_grasp.safety_failure is not None:
    raise RuntimeError(
        "Teacher unsafe physics; stopped PPO before the next optimizer update. See [UNSAFE] snapshot."
    )
```

**直接删除这个判断，不需要替代代码。**

删除后，`step()` 保持：

```python
def step(actions):
    result = original_step(actions)
    observations, rewards, dones, extras = result

    if not torch.isfinite(observations["policy"]).all() or not torch.isfinite(rewards).all():
        raise RuntimeError("Nonfinite Teacher observation or reward")

    s = raw._teacher_grasp
    # 下方原有的奖励统计保持不变
```

其中，非有限数值检测暂时保留，避免 NaN/Inf 直接进入 PPO 优化器。它不是额外的动作限制。若要做到与原始代码完全一致，还需单独核对其逐环境终止与重置时序；不能仅通过删除检查来保证数值安全。

### 2. 不需要修改的部分

| 项目 | 处理 |

| `mdp/events.py` | 不修改 |

| RSL-RL 的 `runner.learn()` | 保留 |
| 额外安全限制 | 不新增 |

**注意：** 如果你已经应用之前的“删除额外异常阈值”补丁，该全局停训判断可能已经不存在，无需重复修改。

### 4. 修改后的训练行为

```text
128个并行环境执行 PPO
          ↓
某个环境触发终止条件
          ↓
Isaac Lab 标记该环境 done
          ↓
只重置对应环境
          ↓
其他环境继续运行
          ↓
RSL-RL 正常收集数据并更新 PPO
```

这符合原始 RobustDexGrasp **单环境终止不导致整个训练停止**的基本语义。

需要区分的是：如果 PhysX 本身发生不可恢复的数值错误，或者观测、奖励出现未被环境终止机制处理的 NaN/Inf，训练仍可能报错。这不属于普通环境终止。

**最终建议：只删除上述全局停训判断，不增加任何替代限制，也不修改 PPO 算法。** 这解决的是首次异常导致全部训练停止的问题，不代表当前抓取物理问题已经修复。
